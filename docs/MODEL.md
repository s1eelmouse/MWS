# Финальная модель

> **Внимание: пакет организаторов 2.1.** Все числа в этом файле — по старому
> пакету. Новый baseline 2.1: T 0.4706, S 0.5345, P/R 0.3348/0.3805; цель
> T ≥0.4506 / S ≥0.5145, отсечение T <0.4206. Старые 0.4351/0.4377 с новыми
> числами напрямую не сравнивать; пересчёт ждёт архив v2.1. См.
> [ORGANIZER_DATA_UPDATE_V2_1.md](ORGANIZER_DATA_UPDATE_V2_1.md).

## Идентичность

| Поле | Значение |
|---|---|
| База | `Qwen/Qwen3-0.6B`, 596 049 920 параметров |
| Текущая production/fallback | `4090-continue-002` (QLoRA, 4 бита, r=16, все линейные слои) |
| Экспериментальный кандидат | `4090-continue-003` (третий цикл, чистый val T 0.4377; шумный — ждёт сервер) |
| Старт второго цикла | `4090-baseline-001` (одна эпоха QLoRA) |
| Второй цикл | LR `1e-4`, +1 эпоха, seed 42, batch 1, max sequence 16 384 |
| Объединённая модель | `out/merged-4090-continue-002`; кандидат — `out/merged-4090-continue-003` |
| Контракт | старые адаптеры — `3ee403f3…a274`; схема v2 — `40e9c449…2654` (принимаются оба) |
| Формат | constrained JSON по `Facts.model_json_schema()`, XGrammar |

**Статус.** `continue-002` подтверждён на чистом и шумном val и остаётся
production/fallback. `continue-003` — реальный третий цикл обучения (246 шагов,
`eval_loss 0.1298`, adapter + merged + полный val), но пока **экспериментальный
кандидат**: без шумного val его нельзя объявлять основной моделью.
`docs/experiments/` — это отчёты и снимки для воспроизводимости, а не веса;
не путать каталог отчёта с каталогом адаптера `out/4090-continue-003`.

Для пакета 2.1 схема разрешает пустое или отсутствующее `object.name`; старые
адаптеры с подписью `3ee403f3…a274` продолжают загружаться, новый контракт —
`40e9c449…2654`. Это ещё не проверено на новых gold: пакет 2.1 не получен.

Хеши данных и стартового адаптера записаны в `out/4090-continue-002/experiment.json`:
train `041dacaa…d6a`, val `a2cd8a6e…19e`, schema `63118114…050`.
Веса в Git не входят: они лежат в `out/` на сервере и исключены из репозитория.

`continue-003` — это **три прохода по train суммарно** (1 эпоха baseline + 1 эпоха
continue-002 + 1 эпоха continue-003), но **не один запуск `--epochs 3`**: каждый
цикл — отдельный запуск с `--epochs 1`, новым оптимизатором и сбросом расписания.
Поэтому его нельзя называть чистым A/B «1 эпоха против 3 эпох».

## Инференс

```bash
export MAX_INPUT_TOKENS=12288
export MAX_NEW_TOKENS=4096
export MAX_SEQUENCE_TOKENS=16384
export JSON_CONSTRAINED=1
export JSON_GRAMMAR_BACKEND=torch_native   # если Triton JIT не собирается
export TEMPORAL_NORMALIZATION=task         # по умолчанию
python -u src/benchmark.py \
  --input data/organizer/val.jsonl \
  --model out/merged-4090-continue-002 \
  --device cuda --batch-size 2 \
  --output-dir out/json-constrained-continue-002-full-001
```

`benchmark.py` после генерации сам применяет пакетный шаг `task`: переносит
даты внутри серий и пересчитывает официальные метрики по уже исправленным
предсказаниям. В каталоге прогона появляется `temporal-audit.jsonl`, а в
`report.json` — `temporal_postprocess`. Поэтому строка «`task` + серии» в таблице
получается одним запуском benchmark, без ручной операции.

Для аудита уже сохранённых предсказаний тот же шаг доступен отдельно:

```bash
python src/postprocess_dates.py \
  --input data/organizer/val.jsonl \
  --pred out/json-constrained-continue-002-full-001/predictions.jsonl \
  --output-dir out/continue-002-task \
  --mode task
python src/eval.py --gold data/organizer/val.jsonl \
  --pred out/continue-002-task/predictions.jsonl --json out/continue-002-task/eval.json
```

HTTP-сервис (`src/serve.py`) применяет пофактные правила `task`; перенос дат
между звонками серии доступен только пакетному benchmark/постобработке, потому
что сервис обрабатывает один звонок.

**Контракт batch vs HTTP.** Пакетный шаг сортирует звонки серии по `call_index`
и переносит только статус «принята» в пределах одного `account_id`; истории
разных аккаунтов не смешиваются (`tests/test_temporal_task.py`). `/extract` и
`/extract_batch` в Transformers-пути серийного переноса не делают — для демо с
серией нужен benchmark/постобработка или отдельный batch-контракт. В vLLM-пути
пока нет `salvage_sources`, поэтому для полной семантики используйте
Transformers-путь. Это известное ограничение, а не скрытая разница метрик.

## Качество на полном val

383 звонка, официальный оценщик:

| Вариант | temporal_recall | state_accuracy | precision / recall | grounding | формат |
|---|---:|---:|---:|---:|---:|
| База glm-5.3 (пересчёт) | 0.4205 | 0.3194 | 0.219 / 0.249 | 0.691 | 91 % |
| `continue-002`, без дат | 0.3566 | 0.3852 | 0.4008 / 0.4119 | 0.7987 | **100 %** |
| `continue-002`, `task` на звонок | 0.4000 | 0.3852 | 0.4008 / 0.4119 | 0.7987 | **100 %** |
| `continue-002`, `task` + серии | **0.4237** | **0.3852** | **0.4008 / 0.4119** | **0.7987** | **100 %** |
| `continue-003`, `task` на звонок | **0.4351** | **0.3949** | **0.4149 / 0.4136** | **0.8047** | **100 %** |
| `continue-003`, `task` + серии | **0.4377** | **0.3949** | **0.4149 / 0.4136** | **0.8047** | **100 %** |

Скорость: `continue-002` — 6,90 с/звонок, `continue-003` — 7,37 с/звонок
(batch 2, RTX 4090), VRAM reserved 6,2 ГиБ, 0 отказов. Режим `task` распознаёт
типичные ASR-искажения cue-слов («вчира», «чирез», «сегадня»); для `action`
используются только точные cue.

Шумный val (`--level 0.15 --seed 42`) подтверждён для `continue-002`:
`temporal_recall` **0.4074** после `task`, state 0.3451, precision / recall
0.3758 / 0.3805, grounding 0.7806, формат **100 %**. На одном звонке невалидный
источник: выброшен только плохой факт, остальные 3 сохранены. Для
`continue-003` шумный прогон ещё не завершён; до него 002 остаётся fallback.

## Ограничения

- `service_state` и `tariff` остаются слабыми: историческое начало или день
  внутри «месяца назад» не выводятся из текущей реплики.
- `agreement` использует эвристику «время события при явном будущем времени»;
  на train её точность 0.383, потому что корпус смешивает время события и
  время заявления.
- Перенос даты «принята» между звонками серии работает только в пакетном
  режиме и только внутри одного `account_id`.
- Это измерение на val и локальном шумном стрессе, не на скрытом
  adversarial-срезе.
