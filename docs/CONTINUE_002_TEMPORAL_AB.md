# Проверка дат второй модели по полученным предсказаниям

Последующая интеграция ограниченной памяти сохранила результат этого контроля.
Новые ограничения и проверка ресурсов описаны в
[history-merged-005](experiments/4090-continue-002/evaluations/history-merged-005/README.md).

14.11.2026. Ветка `feat/temporal-binding-v2`, правила зафиксированы в `68a3197`.

## Результат и выбор

Для единого поведения файла и HTTP выбираем **`task` + явно включённую новую
историю** как кандидат для серверной проверки. На полном val это даёт
**temporal_recall 0.4105**, state_accuracy **0.3852**, формат **100 %**.
Допуск по обеим метрикам выполнен на этом val. `binding` оставляем выключенным.

Прежний пакетный алгоритм имеет **более высокую метрику 0.4237**. Новая история
не превосходит его по качеству: ограничения переноса стоят 10 верных пар дат.
Нужно показывать оба результата и различие протоколов. Проверка реальной
генерации/HTTP на GPU с выбранными настройками ещё не выполнена.

## Проверка входа

Полученный `predictions.jsonl`: 680 719 байт, 383 уникальных звонка,
1896 фактов, 760 совпадений из 1845 эталонных фактов. Все ID совпадают с val;
схема и источники корректны. Пересчёт всех официальных метрик точно
совпал с `metrics.json` из `bbb.tar`: это нужный прогон `4090-continue-002`.
Точных дублей нет. Исходный файл скопирован в новый каталог и не изменялся.

SHA256 предсказаний:
`856bab3c9b488b67994b68cbe9b19a4976ab0bf4b75dd407d092baacb2d1b1b5`.

## Сравнение на одном наборе фактов

| Режим дат | Верные пары / 760 | temporal_recall | state_accuracy |
|---|---:|---:|---:|
| Даты модели | 271 | 0.3566 | 0.3852 |
| `conservative` | 277 | 0.3645 | 0.3820 |
| `task`, без истории | 304 | 0.4000 | 0.3852 |
| **`task` + новая история** | **312** | **0.4105** | **0.3852** |
| `binding`, без истории | 303 | 0.3987 | 0.3852 |
| `binding` + новая история | 311 | 0.4092 | 0.3852 |
| Прежний пакетный `main`, код `ee4b695` | 322 | **0.4237** | 0.3852 |

Во всех вариантах precision 0.4008, recall 0.4119 и grounding 0.7987.
Количество, порядок и все поля фактов, кроме дат, неизменны. Формат — 100 %.
Прежняя версия воспроизведена отдельно из закреплённых исходников, а не взята
только из документации.

- Новая история против `task` без истории: **8 исправлений, 0 регрессий**;
  изменены 20 полей, 19 у сопоставленных фактов.
- `binding` против `task`: 1 исправление, 2 регрессии, суммарно −1 пара.
  С историей у него также −1 пара относительно `task` с историей.
- `task` против дат модели: 55 исправлений, 22 регрессии, суммарно +33 пары.
  Отсутствие регрессий у компонента истории не означает отсутствия регрессий
  у всей цепочки нормализации.
- Новая история против прежнего пакета: 10 ранее верных пар стали неверными
  по эталону, исправлений нет. Это измеренная цена дополнительных ограничений.

База temporal 0.4205 → цель **0.4005**. При 760 совпадениях нужно минимум
305 верных пар; новая история даёт 312. Одиночный `task` даёт 304 и не проходит
этот допуск. Консервативная цель state по отчёту организаторов — 0.3283.
Это проверка на val, а не результат скрытого теста или полного выполнения кейса.

## Протокол и время

Правила и схема не менялись после получения файла. Gold доступен только
оценщику; в правила переданы `CallInput` без эталонных фактов. Обучение Qwen
и повторная генерация не запускались. Официальный оценщик и подпись адаптера
остались прежними. Файл, поток по одному звонку и batch 2 дали одинаковые даты
на всех 383 звонках. Проверка не заменяет реальный GPU/HTTP-прогон модели.

Полная постобработка `task` + история заняла около 0.244 с на CPU без записи
файлов и оценки. Только память истории — медиана 0.046 с, 5 повторов,
с копированием/сортировкой, без модели, календаря и JSON I/O. Эти числа не являются
скоростью генерации или доказательством ускорения относительно учителя.

## Следующий шаг на сервере

Использовать существующую merged-модель `out/merged-4090-continue-002`:

```bash
export TEMPORAL_NORMALIZATION=task
export TEMPORAL_SERIES_HISTORY=1
export TEMPORAL_SERIES_MAX_ENTRIES=10000

python src/benchmark.py --input data/organizer/val.jsonl \
  --model out/merged-4090-continue-002 --device cuda --batch-size 2 \
  --warmup-batches 1 --output-dir out/continue-002-history-serving-001
```

Сохранить прежние проверенные лимиты токенов, параметры constrained decoding
и окружение сервера. Выходной каталог должен быть новым. Этот запуск проверяет
живую генерацию, память и включённое в задержку время правил; результаты могут
отличаться от обработки сохранённых предсказаний. Для HTTP — один worker,
хронологические запросы, стабильные ID клиента/заявки и чистый процесс перед
независимым прогоном. `/health` показывает настройки. В Docker передать
переменные внутрь контейнера. Полный протокол — [TEMPORAL_BINDING_V2.md](TEMPORAL_BINDING_V2.md).
