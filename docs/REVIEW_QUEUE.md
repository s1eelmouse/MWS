# Review queue: выборочная проверка спорных фактов

`src/review_queue.py` строит детерминированную очередь фактов, которые стоит
проверить сильной моделью или человеком. Это не teacher API и не разметка: скрипт
читает только звонки и предсказания модели, gold отбрасывается на границе
`as_call`. Никакие ответы не принимаются автоматически — очередь только
расставляет приоритеты.

## Зачем

Полная проверка всех фактов дорогая, а основная масса предсказаний тривиальна.
Очередь выделяет случаи, где модель могла ошибиться:

| Причина | Что означает |
|---|---|
| `source_turn_missing` | `source.turn_idx` не существует в звонке |
| `source_speaker_mismatch` | speaker факта не совпадает с speaker реплики |
| `competing_current_values` | несколько текущих значений у одного `object + attribute` |
| `low_value_support` | значение слабо подтверждается словами реплики-источника |
| `date_not_supported_by_source` | дата есть, но в источнике нет временного выражения |
| `possible_offer_or_hypothesis` | тариф/договорённость похожи на предложение или условие |
| `long_agreement` | длинная свободная формулировка `agreement` |

Приоритеты: `3` — источник/конкурирующие состояния, `2` — дата/поддержка/
гипотеза, `1` — длинная формулировка. Внутри приоритета сначала идут факты с
наименьшей поддержкой.

## Запуск

```bash
python src/review_queue.py \
  --input data/organizer_v2_1/val.jsonl \
  --pred out/full-val-003-v2-001/predictions.jsonl \
  --output-dir out/review-queue-003-v2-200 \
  --max-items 200
```

`--max-items 0` пишет всю очередь; `200` оставляет верхушку для проверки.
На выходе:

- `queue.jsonl` — по факту: `call_id`, `fact_index`, `fact`, `reasons`,
  `priority`, `value_support`, реплика-источник с соседними репликами;
- `candidate_turns` — top-3 реплики по лексической поддержке значения для
  source-related причин; текущий `turn_idx` помечен `is_current`, но **не
  заменяется** автоматически;
- `summary.json` — сколько всего фактов, сколько попало в очередь, по причинам,
  атрибутам и приоритетам, сколько selected.

## Что получилось на 003

Сохранённые предсказания 003, полный val 2.1:

- 1839 фактов;
- в очередь попали 1037 (56,4 %) — эвристика намеренно широкая;
- для проверки выбраны **200 фактов (10,9 %)** — top by priority/support;
- причины: `low_value_support` 636, `possible_offer_or_hypothesis` 299,
  `date_not_supported_by_source` 287, `competing_current_values` 36,
  `long_agreement` 9, `source_speaker_mismatch` 3;
- по атрибутам: `agreement` 668, `ticket_status` 144, `service_state` 115,
  `tariff` 64, `action` 46.

Высокая доля очереди — это нормально: `agreement` и перефразированные значения
плохо проверяются лексическим совпадением. Для дорогой проверки берём верхние
200, а не всю очередь.

Кандидаты показывают альтернативы, но автоматическая замена `turn_idx` по
support не включена: на сохранённых 003 exact-правило меняло 353 источника и
снижало grounding 0.7121 → 0.6450. Причина — значения часто повторяются в
нескольких репликах; правильная ссылка не всегда самая лексически похожая.

## Как проверять

1. Взять элемент `queue.jsonl`.
2. Показать проверяющему только `fact`, `source` (реплика ±1) и вопрос:
   «Подтверждается ли факт этой репликой?»
3. Ответ: `accept`, `reject` или `correct` с исправленными
   `object/value/valid_from/valid_to/source`.
4. Любой ответ всё равно проходит `Facts.model_validate` и
   `source_problems`; при сомнении факт отбрасывается, а не «чинится».
5. Все решения писать в отдельный audit JSONL с `call_id`, `fact_index`,
   причиной и версией проверяющего.

Teacher API в локальной валидации запрещён `AGENTS.md`; для продукта нужны
разрешение организаторов, проверка приватности и фиксация модели/версии
проверяющего. На хакатоне достаточно очереди и дизайна, без реальных вызовов.

## Ограничения

- Это эвристики, а не вероятность ошибки: `low_value_support` часто срабатывает
  на честных перефразах.
- Нет token-level confidence: текущая генерация не сохраняет logprobs.
- Очередь не оценивает смысловую правильность и не заменяет val/scorer.
- Она не должна использоваться для обучения на val или для просмотра gold.
