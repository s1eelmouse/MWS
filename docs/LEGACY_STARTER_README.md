# CompactFactExtraction — стартовый репозиторий

Компактная модель читает обращение в техподдержку и возвращает факты в виде JSON.
Путь решения: разметка большой моделью → дообучение малой модели (QLoRA) → слияние →
сервис → замеры качества, размера и скорости.

Все команды запускаются из корня репозитория.

## Что где лежит

| Файл | Зачем |
| --- | --- |
| `src/config.py` | Какая модель, куда сохранять, лимиты длины |
| `src/schema.py` | Схема фактов и текст запроса — общие для обучения и сервиса |
| `src/label.py` | Разметка обращений моделью-учителем |
| `src/check_data.py` | Проверка разметки: схема и дословность цитат |
| `src/split.py` | Деление на train, val, test |
| `src/train.py` | Дообучение QLoRA |
| `src/merge.py` | Слияние адаптера с моделью |
| `src/extractor.py` | Загрузка модели и извлечение фактов |
| `src/serve.py` | Сервис FastAPI: `/extract`, `/extract_batch`, `/health` |
| `src/serve_vllm.py` | Тот же сервис поверх vLLM |
| `src/predict.py` | Прогон файла без сервиса, пачками |
| `src/eval.py`, `src/metrics.py` | F1 по полям, доля валидных ответов, задержка |
| `src/mcp_server.py` | Инструмент для агента (nanobot) |
| `data/sample.jsonl` | 32 выдуманных обращения с разметкой |

`data/sample.jsonl` нужен только чтобы убедиться, что цепочка запускается. Учить на нём
модель для сдачи нельзя: примеров слишком мало.

## 1. Окружение

Нужны видеокарта NVIDIA и [uv](https://docs.astral.sh/uv/). Подходит Python 3.11–3.13;
uv сам скачает нужную версию.

```powershell
uv venv --python 3.12
.venv\Scripts\Activate.ps1
uv pip install torch --torch-backend=auto
uv pip install -r requirements.txt
```

Скачается около 2 ГБ, окружение займёт 3,3 ГБ. Проверка, что PyTorch видит видеокарту
(должно напечатать `True`):

```powershell
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
```

Если PowerShell не даёт выполнить `Activate.ps1`, вызывайте интерпретатор окружения напрямую:
`.venv\Scripts\python.exe src\train.py`.

В Kaggle и Colab PyTorch уже установлен, там достаточно `pip install -r requirements.txt`.

### Перед обучением освободите память

В Windows память видеокарты расходует ещё и общую память системы (ОЗУ плюс файл подкачки).
Если она занята браузером и IDE, обучение падает с `CUDA out of memory`, хотя на видеокарте
место есть. Поэтому перед обучением и слиянием закройте тяжёлые программы: браузер, PyCharm,
IDEA, живые обои, игры. Сколько видеопамяти занято другими программами, покажет `nvidia-smi`.

## 2. Проверка цепочки на учебных данных

Сначала то, что работает без видеокарты:

```powershell
python -m unittest discover tests
python src/check_data.py data/sample.jsonl
python src/split.py --input data/sample.jsonl
```

Затем обучение самой маленькой модели, слияние и оценка. При первом запуске скачается
модель (1,5 ГБ). Числа будут плохими, F1 может выйти и нулевым: на трёх десятках примеров
модель ничему не научится. Цель — увидеть, что каждый шаг доходит до конца.

```powershell
$env:BASE_MODEL = "Qwen/Qwen3-0.6B"
python src/train.py --epochs 5
python src/merge.py
python src/predict.py --input data/test.jsonl --output out/pred.jsonl
python src/eval.py --gold data/test.jsonl --pred out/pred.jsonl
```

Если `train.py` пишет «Не хватило памяти», запустите его с `--batch-size 2`.

Сервис и замер задержки. Первое окно:

```powershell
uvicorn serve:app --app-dir src --port 8000
```

Второе окно:

```powershell
python src/eval.py --gold data/test.jsonl
python src/eval.py --gold data/test.jsonl --workers 8
```

Сервис можно проверить и руками: откройте `http://127.0.0.1:8000/docs`. Чтобы он был виден
с других машин, добавьте к команде запуска `--host 0.0.0.0`.

## 3. Работа со своими данными

1. Положите обращения в `data/raw.jsonl`, по одному в строке: `{"text": "..."}`.
2. Поменяйте поля в `src/schema.py` на те, что назовут организаторы.
3. Разметьте данные моделью-учителем. Сначала проба, потом весь файл:

   ```powershell
   $env:TEACHER_URL = "https://адрес-сервиса/v1"
   $env:TEACHER_KEY = "ключ"
   $env:TEACHER_MODEL = "имя-модели"
   python src/label.py --limit 20
   python src/label.py
   ```

4. Проверьте разметку скриптом и глазами, ошибки исправьте прямо в `data/labeled.jsonl`:

   ```powershell
   python src/check_data.py data/labeled.jsonl
   ```

5. Разделите данные, обучите, слейте, оцените:

   ```powershell
   python src/split.py --input data/labeled.jsonl
   python src/train.py
   python src/merge.py
   python src/predict.py
   python src/eval.py --pred out/pred.jsonl
   ```

Строка «до дообучения» для таблицы результатов:

```powershell
python src/predict.py --model Qwen/Qwen3-1.7B --with-schema --output out/pred_base.jsonl
python src/eval.py --pred out/pred_base.jsonl
```

Сравнение моделей. Каждой модели — свои папки, иначе результаты затрут друг друга:

```powershell
$env:BASE_MODEL = "MTSAIR/Cotype-Nano"
$env:ADAPTER_DIR = "out/adapter-nano"
$env:MERGED_DIR = "out/merged-nano"
```

Папка `data/` закрыта от git, кроме учебного примера: данные организаторов могут быть
закрытыми, а ключи в репозиторий попадать не должны.

## 4. Скорость: что показал замер

Замер 10.11.2026: Windows 10, RTX 4060, Qwen3-0.6B, сервис `serve.py`, 32 учебных обращения.
Модель обучена на 28 примерах и отвечает длиннее и хуже настоящей, поэтому числа — ориентир
для сравнения вариантов, а не итог.

| Режим | Задержка p50 | Обращений в секунду |
| --- | --- | --- |
| Запросы по одному, до доработок | 2,7 с | 0,3 |
| Запросы по одному | 1,65 с | 0,6 |
| 8 параллельных запросов, до доработок | 22,8 с | 0,3 |
| 8 параллельных запросов | 6,8 с | 1,0 |
| 16 параллельных запросов | 9,6 с | 1,7 |
| `predict.py`, пачки по 16 | — | 2,0 |

Что из этого следует:

- **Время ответа — это число токенов в ответе.** Каждый токен ответа стоит около 53 мс,
  и почти всё это время уходит не на вычисления, а на накладные расходы Windows и Python:
  видеокарта при этом загружена на четверть. Длина запроса на задержку почти не влияет.
  Отсюда главный рычаг: чем короче ответ модели, тем быстрее сервис.
- **Размер модели на этой машине на задержку почти не влияет.** У Qwen3-0.6B и Qwen3-1.7B
  одинаковое число слоёв, поэтому сравнивайте их по качеству, а задержку перемерьте.
- **Пачка стоит почти столько же, сколько одно обращение.** `serve.py` склеивает
  одновременные запросы в пачку (до 16), `predict.py` обрабатывает файл пачками.
- **Одиночный запрос ускорен копированием из обращения.** Факты — дословные цитаты,
  поэтому модель за шаг проверяет до 10 скопированных токенов (`PROMPT_LOOKUP_TOKENS`
  в `config.py`). На замере ответы совпали с обычной генерацией в 16 случаях из 16.
- **На Linux и в vLLM накладные расходы ниже,** но здесь это не измерялось.

После смены схемы поставьте `MAX_NEW_TOKENS` в `config.py` чуть больше самого длинного
эталонного ответа: один «заболтавшийся» ответ задерживает всю пачку.

## 5. Вариант с vLLM

vLLM работает только на Linux; на Windows его запускают в WSL. Диск `D:` в WSL виден
как `/mnt/d`. vLLM считает параллельные запросы одной пачкой и выдаёт ответ строго по
JSON-схеме: значение не из списка допустимых модель вернуть не сможет.

В WSL:

```bash
uv venv --python 3.12 && source .venv/bin/activate
uv pip install vllm --torch-backend=auto
vllm serve out/merged --served-model-name extractor --max-model-len 4096 --port 8001
```

В Windows, в окружении проекта:

```powershell
uvicorn serve_vllm:app --app-dir src --port 8000
```

Адреса у сервиса те же, поэтому `eval.py` и `mcp_server.py` менять не нужно.

## 6. Демо с агентом

`src/mcp_server.py` превращает сервис в инструмент `extract_facts` для агента.

```powershell
uv pip install "mcp>=2"
```

В настройки nanobot (`~/.nanobot/config.json`) добавьте сервер, указав полный путь к файлу
и интерпретатор окружения проекта:

```json
{
  "tools": {
    "mcpServers": {
      "extractor": {
        "command": "C:/путь/к/репозиторию/.venv/Scripts/python.exe",
        "args": ["C:/путь/к/репозиторию/src/mcp_server.py"]
      }
    }
  }
}
```

## Что проверено

Состояние на 10.11.2026. Машина: Windows 10, RTX 4060 8 ГБ, 16 ГБ ОЗУ, Python 3.12.13.
Версии: torch 2.14.1+cu130, transformers 5.22.2, peft 0.21.2, accelerate 1.15.0,
bitsandbytes 0.50.2, fastapi 0.162.2, uvicorn 0.54.0, pydantic 2.14.3, mcp 2.3.0.

Запускалось на видеокарте с моделью Qwen3-0.6B и учебными данными:

- установка окружения командами из раздела 1;
- `train.py`: 5 эпох на 28 примерах за 50 секунд, ошибка на train упала с 1,96 до 0,31,
  пик видеопамяти 1,5 ГБ при `--batch-size 2`; вариант `--no-4bit` тоже доходит до конца;
- `merge.py`: модель 1,2 ГБ; её предсказания совпали с моделью с адаптером (160 токенов из 160);
- `predict.py` и `eval.py --pred`, в том числе базовая модель с `--with-schema`;
- `serve.py`: `/extract`, `/extract_batch`, `/health`, `/docs`; пустой текст, текст на
  20 000 символов и посторонние символы дают ответ 200, запрос не по формату — 422,
  ответов 500 не было; F1 через сервис совпал с прогоном из файла;
- `mcp_server.py`: клиент MCP видит инструмент и получает ответ; при выключенном
  сервисе инструмент возвращает ошибку, а не падает;
- расчёт ошибки в `train.py` сверен со стандартным: расхождение в третьем знаке
  (округление bfloat16), содержимое дополнения на результат не влияет.

Запускалось без видеокарты:

- тесты `tests/`: 25 из 25; `check_data.py` и `split.py` на учебных данных;
- `label.py` с заглушкой учителя: проба с `--limit`, продолжение после остановки, повтор
  после временного сбоя, остановка при неверном ключе, пропуск ответа не по схеме;
- `serve_vllm.py` с заглушкой vLLM: запрос уходит со схемой ответа и выключенным
  размышлением, сбой vLLM превращается в запасной ответ.

Не проверялось:

- настоящий vLLM в WSL и подключение `mcp_server.py` к nanobot;
- модели Qwen3-1.7B и MTSAIR/Cotype-Nano;
- обучение на настоящих данных: все числа качества здесь получены на учебном примере.

После первого успешного запуска закрепите версии: `uv pip freeze > requirements.lock.txt`.

## Частые проблемы

| Что видно | Что делать |
| --- | --- |
| `train.py`: «Не хватило памяти» или `CUDA out of memory` при свободной видеокарте | Закройте браузер, IDE и другие тяжёлые программы; запустите с `--batch-size 2` или `1` |
| `MemoryError`, `bad allocation` или «Файл подкачки слишком мал» (ошибка 1455) | То же: системе не хватает общей памяти. Закройте программы и запустите ещё раз |
| Каждый запрос к сервису идёт на 2 секунды дольше | В адресе стоит `localhost`. В Windows пишите `127.0.0.1` |
| `KeyError: 'qwen3'` | Обновите transformers: `uv pip install -U transformers` |
| «PyTorch не видит видеокарту» | Переустановите PyTorch командой с `--torch-backend=auto`, обновите драйвер NVIDIA |
| Предупреждения `triton not found`, `unauthenticated requests`, `use_reentrant` | Безвредны, ничего делать не нужно |
| Модель без дообучения отвечает не по схеме | Запускайте её с `--with-schema` (в сервисе — `WITH_SCHEMA=1`) |
| Ответ `invalid_json`, хотя JSON на вид правильный | Значение не из списка допустимых или нет обязательного поля: нужно больше примеров при обучении либо vLLM со схемой |
| После обучения F1 низкий, а ошибка на val маленькая | Проверьте, что сервис запущен на новой папке `out/merged`, а запрос в `schema.py` не менялся после обучения |
| `eval.py` показывает 0% валидного JSON | Сервис не запущен или слушает другой порт: проверьте `http://127.0.0.1:8000/health` |
