# Основная модель и следующие проверки

Дата: 14.11.2026. Работаем только с **Qwen3-0.6B**. Новое обучение не запускать
автоматически: сначала сравнить правила дат на уже сохранённых предсказаниях.

## Что известно о второй эпохе

Основной кандидат команды — `4090-continue-002` с constrained decoding.
По командному отчёту, полный val: 383 звонка, 0 отказов, формат 100 %,
precision / recall 0.4008 / 0.4119, grounding 0.7987, state_accuracy 0.3852.

| Даты второй модели | temporal_recall | Что это означает |
|---|---:|---|
| Без правил | 0.3566 | Ниже отсечения 0.3705 по пересчитанной базе |
| `task`, без истории | 0.4000 | Выше отсечения, ниже цели 0.4005 |
| `task` + прежняя пакетная история | 0.4237 | В пределах 0.02 от базы 0.4205 при той политике |
| Новая история / `binding` | не измерено | Новых предсказаний второй модели на ноутбуке нет |

Нельзя утверждать, что режим HTTP по умолчанию достигает 0.4237: это число
получено прежним пакетным переносом. Новая история теперь поддерживается и
HTTP-сервисом, но содержит дополнительные ограничения, поэтому требует A/B.

## Решение по датам

1. `task` оставить режимом по умолчанию; история включается явно.
2. Новая история использует только предыдущие предсказания того же клиента
   и идентифицированной заявки. Ментор формально разрешил историю (Q07).
3. На первой модели история дала 0.4008 → **0.4064**, 4 исправления без
   регрессий против `task` без истории. Прежний пакет давал 0.4147:
   новая политика не объявляется улучшением относительно него.
4. `binding` оставить экспериментом: отдельно он дал 2 исправления / 7
   регрессий, с историей — на 4 верные пары меньше относительно нового `task`
   с историей. Причин менять умолчание нет.
5. Q03 и Q10 остаются неоднозначными. Не менять по заметкам семантику
   `agreement` и не придумывать неизвестное начало исторических состояний.

- На сервере выполнить CPU-сравнение четырёх вариантов дат второй модели
  по командам из памятки; повторная генерация и обучение для этого не нужны.
- По результатам выбрать режим и явно записать наличие истории. Затем
  проверить обычный инференс и HTTP с теми же настройками.
- Снять три точки ресурсов одной модели: GPU batch 1, GPU batch 4,
  CPU batch 1. Качество измерить в каждой точке.
- Продемонстрировать эффект дат и истории, регрессии и ограничения.
  Время учителя и сокращение GPU-секунд в 5 раз пока не доказаны.
