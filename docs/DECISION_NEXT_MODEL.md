# 1.7B и следующая эпоха: короткое решение

Дата: 14.11.2026. Контекст: constrained decoding уже даёт 0 отказов и 100 %
валидного формата на полном val, но `temporal_recall` ниже отсечения.

| Вариант | `temporal_recall` | `state_accuracy` | precision / recall | grounding | формат |
|---|---:|---:|---:|---:|---:|

Полный val второй эпохи закончен: 383 звонка, 0 отказов, формат 100 %. После
дат `task` падение `temporal_recall` от базы 0.0021 — в пределах допуска 0.02;
`state_accuracy`, precision, recall и grounding выше базы. Без переноса дат
между звонками серии (HTTP-режим) `temporal_recall` 0.3947 — выше отсечения,
но ниже цели 0.401.

## Варианты

| Вариант | Плюсы | Риски | Стоимость |
|---|---|---|---|
| 1.7B QLoRA | верхняя точка кривой, больше capacity | полные 1,72B > лимита 1,5B; без эмбеддингов 1,409B. Нужно письменное разрешение ментора и обход проверки в `train.py` | ориентировочно 1,5–2,5× от 0,6B (не измерено) |
| Вторая эпоха 0,6B | уже есть `4090-continue-002`; дешевле | исходный экспорт был непригоден, но constrained preview дал P/R 0.420/0.412 и state 0.455 против 0.346/0.373/0.394; temporal 0.286 против 0.290. Полный val идёт | только inference для проверки |
| Стоп, даты кодом | самый прямой путь к `temporal_recall` | зависит от качества нормализатора | работа уже идёт |

## Решение

1. **Основная модель — `4090-continue-002`.** Полный val: P/R 0.4008/0.4119,
   temporal 0.3566, state 0.3852, grounding 0.7987, 0 отказов. Это лучше
   baseline по всем пяти метрикам, поэтому вторая эпоха становится основной.
2. **Даты — детерминированный режим `task`, включён по умолчанию.** На полном
   val он поднимает `temporal_recall` до 0.4184 (пакет) или 0.3947 (один звонок)
   без изменения precision/recall/grounding. `state_accuracy` остаётся 0.3852.
3. **Новую эпоху 0,6B не запускать.** Прирост уже получен; следующий цикл без
   новой причины будет переобучением.
4. **1.7B не тренировать.** Критерий 0.02 по `temporal_recall` выполнен на 0,6B,
   а 1,72B требует письменного разрешения и выходит за лимит 1,5B. Риск
   дисквалификации не оправдан.

## Что проверить у ментора

- Считать ли лимит 1,5B по полным параметрам или без эмбеддингов (Q05).
- Достаточно ли трёх режимов одной 0,6B для кривой «ресурсы × качество» (Q13).
- Какие числа базы официальны: отчёт или пересчёт (Q01).
