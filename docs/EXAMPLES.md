# Небольшие примеры для контракта

Синтетические примеры для проверки правил и защиты. Это не файлы данных и не
промпты: они не подаются модели автоматически и не заменяют `val`. Формат входа —
`CallInput`, эталонные `facts` в запрос не попадают.

## 1. Относительные даты и смена статуса

```json
{
  "call_id": "example:relative-dates",
  "started_at": "2026-03-11T10:00:00",
  "turns": [
    {"idx": 0, "speaker": "client",
     "text": "Вчера пропал интернет, а со вторника не работает телевизор."},
    {"idx": 1, "speaker": "operator",
     "text": "Заявку приняли сегодня. Мастер приедет в пятницу после двух."},
    {"idx": 2, "speaker": "client", "text": "Да, в пятницу подходит."}
  ]
}
```

Ожидаемое поведение `task`:

- `service_state` «нет доступа в интернет» — `valid_from = 2026-03-10` (вчера);
- `service_state` «телевизор не работает» — `valid_from = 2026-03-10`
  («со вторника» = ближайший вторник до звонка);
- `ticket_status` «принята» — `valid_from = 2026-03-11` («сегодня»);
- `agreement` «выезд специалиста» — `valid_from = 2026-03-13` («в пятницу»,
  ближайшая пятница после звонка).

Если модель ошиблась в дне, код пересчитывает дату от `started_at`; если cue нет,
дата остаётся моделью (кроме `action`, где берётся время звонка).

## 2. Подтверждение и отклонённое предложение

```json
{"call_id": "example:refusal", "started_at": "2026-03-11T12:00:00",
 "turns": [
   {"idx": 0, "speaker": "operator", "text": "Могу подключить пакет каналов за триста рублей."},
   {"idx": 1, "speaker": "client", "text": "Нет, не надо, мне это не нужно."}
 ]}
```

Ожидаемое поведение: **отклонённое предложение не становится `agreement`**.
Если извлекается факт об отказе, он должен иметь `polarity = -1` и корректный
`source.turn_idx`; «не» само по себе не переворачивает полярность выполненного
действия («перезагрузил — не помогло» остаётся действием с `polarity = 1`).

## 3. Изменение состояния

```json
{"call_id": "example:state-change", "started_at": "2026-03-11T10:00:00",
 "turns": [
   {"idx": 0, "speaker": "client",
    "text": "До вторника интернет работал нормально, а со вторника нет доступа."}
 ]}
```

Ожидаемое поведение:

- «работает нормально» — `valid_to = 2026-03-10`, начало историческое и не
  выдумывается;
- «нет доступа» — `valid_from = 2026-03-10`;
- массовое закрытие `valid_to` у всех одно-значных атрибутов не применяется:
  на полном val оно ухудшало и `temporal_recall`, и `state_accuracy`.

## 4. Неподтверждённая догадка

```json
{"call_id": "example:guess", "started_at": "2026-03-11T12:00:00",
 "turns": [
   {"idx": 0, "speaker": "client", "text": "Наверное, проблема в кабеле, но я не проверял."},
   {"idx": 1, "speaker": "operator", "text": "Возможно, стоит заменить кабель."}
 ]}
```

Ожидаемое поведение: догадка клиента и предложение оператора **не являются
фактами**. Если модель всё же вернула `agreement` с «возможно/если/может»,
такой факт можно отбросить: на полном val это 15–17 лишних `agreement` без
изменения recall и `temporal_recall`. По умолчанию фильтр не включён, чтобы не
удалять трудные, но подтверждённые формулировки.
