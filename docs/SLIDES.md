# Содержание защиты: выбранная 0.6B, релиз 005

Рабочий текст на 8 слайдов, около четырёх минут. Пакет 2.1, полный clean val,
383 звонка. Факты взяты из отчёта `4090-continue-005-noise`.
Старые `defense-deck.pptx/pdf` ещё не пересобраны под этот текст.
Незаполненные ресурсные точки заменить только фактическими измерениями.

## 1. Компактное извлечение фактов из звонков

Qwen3-0.6B, 596 млн параметров. Звонок превращается в факты об услугах,
тарифах, заявках, действиях и договорённостях с датами и источниками.
Релиз 005: T 49,00%, S 55,22%, 383/383 ответов валидны по схеме на clean val.

## 2. Требования кейса

| Показатель | Baseline 2.1 | Граница | 005 |
|---|---:|---:|---:|
| Temporal recall | 47,06% | ≥45,06% | 49,00% |
| State accuracy | 53,45% | ≥51,45% | 55,22% |

Экономия: подтвердить ≥10× по параметрам либо ≥5× по GPU-секундам.
T считается среди сопоставленных фактов с восстановимой датой, а не всех фактов.
Скрытый набор неизвестен; clean val не доказывает устойчивость на нём.

## 3. Архитектура решения

Вход: дата звонка и реплики с ролями/индексами.
Qwen извлекает объекты, значения, полярность, даты и реплику-источник.
XGrammar ограничивает структуру ответа схемой Facts.
Код проверяет каталог, даты и интервалы; восстанавливает явные пропущенные
текущие тарифы/статусы. Ограниченная история связывает принятие одной заявки
между предыдущими звонками того же аккаунта.
Выход: JSON по контракту организаторов через FastAPI.

## 4. Обучение и происхождение весов

005: новый цикл от адаптера 003, train 2.1, чистые и шумные копии — 7 852 звонка.
Одна эпоха расширенного набора, 491 шаг, LR 1e-4, effective batch 16.
QLoRA: NF4 4-bit, LoRA r=16, около 10 млн обучаемых параметров.
Полный размер модели — 596 млн. После merge инференс работает в FP16.
Val не участвует в градиентах. Нет teacher API и молчаливой обрезки входов.
Прирост 005 включает новый train, дополнительное обучение и аугментацию;
отдельный вклад только шума без plain-контроля не установлен.

## 6. Ресурсы и качество

Подтверждённая точка 005: RTX 4090, FP16, batch2, история/правила включены.
383 звонка за 45 мин 07 с; в среднем 7,07 GPU-с на звонок, 509,40 звонка/ч.
Готовность ответа p50/p95 14,33/18,38 с; пик reserved около 4,73 ГиБ.
Загрузка модели и прогрев исключены, обработка правил/истории включена.

Для окончательного слайда нужны три совместимые измеренные точки batch1/2/4
с T и S на оси качества и временем/памятью на оси ресурсов. CPU показывать
отдельно; GPU-секунды для CPU не равны нулю. В качестве сравнительной модели
около 1.5B использовать только согласованную с менторами методику. До замера
не писать «5× быстрее» и не подменять выигрыш быстрыми пустыми ответами.

## 7. Ошибки и ограничения

| Тип | Правильные текущие состояния | Правильные временные пары |
|---|---:|---:|
| Услуги/устройства | 85/309 | 28/119 |
| Тарифы | 85/106 | 20/82 |
| Заявки | 174/208 | 139/292 |

Главный резерв — пропуски услуг и привязка их времени.
У договорённостей 654 несопоставленных предсказания; часть может объясняться
неполнотой разметки и matcher, поэтому нужны примеры, а не ярлык «галлюцинации».
Локальный стресс меняет слова при сохранении gold: результаты разбираем отдельно.
Правила дорабатывались на выданном val, скрытая обобщаемость не доказана.

## 8. Демонстрация и поставка

Показать `/health`: выбранные веса, `case_v2`, recovery и история включены.
Затем заранее проверенный звонок, извлечённый факт, дату и исходную реплику.
Для недоступного сервера иметь запись реального демо.
Передать модель с SHA256, точный конфиг, код, окружение и отчёты измерений.
100% валидного формата относится к проверенным 383 ответам, не означает
100% семантической правильности или гарантию скрытого теста.

Блок идей улучшения от другой части команды добавить отдельно, без смешения
его прототипов с измеренными метриками основной модели.
