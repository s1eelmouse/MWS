# Общая память дат заявок

Объединение реализации Володи (`992b439`, `feat/temporal-binding-v2`) и
локальной реализации ограниченной памяти. Обучение и веса модели не меняются.
Основной режим — `task`; экспериментальный `binding` сохранён, но не выбран:
по проверке Володи на второй модели он уступает `task` на одну верную пару дат.

## Что взяли из двух решений

| Часть | Выбранное решение |
|---|---|
| Правила переноса | Володя: конкретный ID заявки либо номер из имени; одного слова «заявка» недостаточно |
| Приоритет свидетельств | Володя: локальная явная дата, ASR-подсказки и новый эпизод важнее старой даты |
| Время | Володя: строго более ранний `started_at`, а не только `call_index` |
| Интеграция | Володя: единый модуль внутри `Extractor.extract` и vLLM; HTTP получает тот же результат; время входит в benchmark |
| Пределы ресурсов | Наша версия: ограничение аккаунтов, байтов, записей одного аккаунта и времени хранения |
| Изоляция и повторы | Наша версия: отдельные сессии, хеши ключей и входа, проверка конфликтующего повторного запроса |
| Наблюдаемость | Общая: происхождение каждой замены плюс размер, пики, время, вытеснения и причины отказа от переноса |

Используется один движок `src/series_history.py`; второй параллельный cache
и повторная обработка на уровне HTTP не добавлены.

## Дополнительные исправления

- Короткое подтверждение предыдущей реплики может задавать явное начало.
  Свидетельство только об окончании не блокирует восстановление начала.
- Начало и окончание проверяются совместно для всей группы фактов заявки.
  При конфликте нельзя заменить дату лишь у части группы.
- Дата из будущего, некорректный интервал и несовместимые часовые пояса
  не становятся источником новой даты в памяти.
- Новый эпизод с неизвестной датой сохраняет временной барьер без даты.
  Опоздавший запрос старого эпизода не может восстановить старую запись.
- Проверяется соответствие ID входов и результатов; входы не изменяются.
- Прогрев очищает память и её счётчики. Разные настройки истории, каталога,
  декодирования и повторов нельзя молча смешать в ресурсной кривой.

## Включение и пределы

История включается явно. Это сохраняет возможность чистого A/B без памяти.
Для выбранной конфигурации сервера:

```bash
export TEMPORAL_NORMALIZATION=task
export TEMPORAL_SERIES_HISTORY=1
export TEMPORAL_SERIES_MAX_ENTRIES=10000
export HISTORY_MAX_ACCOUNTS=512
export HISTORY_MAX_BYTES=8388608
export HISTORY_TTL_SECONDS=3600
```

Дополнительно код ограничивает один аккаунт 64 записями и 32 КиБ.
Записи вытесняются при заполнении, истекают через час без обновления;
независимые `series.session_id` не смешиваются. Обязателен стабильный
`account_id`; `call_index` для чтения памяти не требуется. Используется только
положительный `ticket_status=принята`, переносится только `valid_from`.

Предел 8 МиБ относится к сериализованным данным записей вместе с ключами.
Python-словари, индексы и временные копии имеют дополнительные накладные расходы;
это не предел RSS процесса. Фактический RSS и VRAM измеряет `benchmark.py`.
Память не хранит транскрипты и эталонные факты. Дополнительных запросов к модели,
токенов в prompt и GPU-тензоров механизм не создаёт.

Память принадлежит backend одного процесса и очищается при перезапуске.
Для связной HTTP-истории нужен **один worker**, хронологические запросы и
новый процесс перед независимым экспериментом. Параллельные обращения могут
завершаться не по порядку: поздно завершившийся старый звонок воздерживается,
а его уже выданные ответы не пересчитываются. Нельзя обещать одинаковые результаты
при любом порядке конкурентных запросов. Ошибочная первая дата модели также
может распространиться; память не доказывает истинность первоначальной даты.

## Где смотреть измерения

- `/health`: `history` содержит настройки, размер, пик, время и счётчики.
- `report.json`: `history_settings`, `history`, `normalization_counts`.
- `calls.jsonl`: `series_decisions` с исходным звонком и временем наблюдения.
- `temporal-audit.jsonl`: решения календаря и памяти.
- `predictions-before-series.jsonl`: снимок до памяти из измеренного backend;
  финальные ответы после памяти — в `predictions.jsonl`.
- `raw-answers.jsonl`: исходные генерации при `SAVE_RAW_RESPONSES=1`.
- `settings.json` общего сценария: переменные режима и ограничений памяти.

Проверка повторов относится к последнему сохранённому наблюдению данной заявки.
Это не долговременный журнал всех запросов. После вытеснения/TTL прежняя запись
недоступна; для независимых оценок нужен чистый процесс.

Текущий [контрольный эксперимент](experiments/4090-continue-002/evaluations/history-merged-005/README.md)
содержит результаты, точные измерения и переносимый скрипт повторения.
Старые отчёты описывают прежние алгоритмы и остаются историческими данными.
