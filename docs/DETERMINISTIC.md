# Календарь и детерминированная обработка

Готовые компоненты работают на CPU без загрузки модели. Они не меняют обучающий
prompt, схему фактов и подпись существующего адаптера. Новое обучение не требуется.

## Что реализовано

| Компонент | Файл | Поведение |
|---|---|---|
| Календарь | `src/temporal.py` | Относительные дни, числовые сроки в днях/неделях/часах/минутах, явные ISO/числовые/словесные даты, дни недели с направлением, периоды недель/месяцев, время суток |
| Привязка к фактам | `src/temporal.py` | Проверяет атрибут, значение и реплику; различает начало и явное завершение; отказывается от конфликтующих/неполных свидетельств |
| Каталог | `src/catalog_normalization.py` | Только однозначное точное совпадение после нормализации регистра, пробелов и оформления; необязательные явно заданные алиасы |
| Говорящий | `src/prediction.py` | Источник — диаризация исходной реплики; прежнее поведение сохранено |
| Дубли | `src/prediction.py` | Удаление только полных совпадений; прежнее поведение сохранено |
| Обработка файлов | `src/postprocess_dates.py` | Новый файл предсказаний, журнал решений и манифест; исходные результаты не перезаписываются |
| Сравнение дат | `src/compare_temporal.py` | Проверяет неизменность фактов/порядка/других полей, считает исправления и регрессии официальным оценщиком |

## Принципы календаря

- Единственная точка отсчёта — `started_at` текущего звонка. Системные часы не используются.
- Сохраняется часовой пояс, если он указан во входе.
- Високосность и границы месяца/года рассчитываются стандартным календарём.
- Невозможные даты не заменяются ближайшими существующими датами.
- «На прошлой неделе» возвращает диапазон календарной ISO-недели, а не выдуманный
  конкретный день. Это не утверждение о политике разметки организаторов.
- «В прошлом месяце» возвращает границы месяца. `shift_calendar_months` сдвигает
  календарный месяц с сохранением числа; при несуществующем числе выбрасывает
  ошибку, а не молча обрезает его.
- Год в неполной дате и день недели требуют направления `past`/`future`; совпадение
  дня недели с днём звонка оставляется неоднозначным.
- «После двух» без дополнительных условий неоднозначно. Публичный API позволяет
  явно выбрать `daytime_hours=True`, тогда это нижняя граница после 14:00.
  Автоматическая привязка фактов эту конвенцию не включает.
- У выражения есть исходный фрагмент, символьные границы, точность, отношение
  (`at`/`after`/`before`/`by`/`period`), правило и причина неопределённости.

Пример программного использования при `PYTHONPATH=src`:

```python
from temporal import extract_time_expressions

items = extract_time_expressions("вчера", "2026-03-01T12:00:00+03:00")
assert items[0].start == "2026-02-28T00:00:00+03:00"

items = extract_time_expressions(
    "завтра после двух", "2026-03-01T12:00:00", daytime_hours=True
)
assert items[0].start == "2026-03-02T14:00:00"
assert items[0].relation == "after"
```

## Что автоматически не угадывается

Неизвестное историческое начало, смысл даты `agreement` (Q10), неоднородные даты
`action`, включительность окончания «до ...», несколько времён в одной части
реплики, вопрос/гипотеза/отрицательный факт и одинаковое свидетельство для разных
объектов. Такие случаи остаются без изменения и получают причину в журнале.

Правила работают только с исходной репликой указанного `source.turn_idx`. Они не
переносят источник на другую реплику по похожести слов и не используют историю
аккаунта. Короткое подтверждение без собственного времени пока не разрешается
автоматически через предыдущую реплику. Это ограничение привязки, а не календаря.

Значения `polarity` не переворачиваются по наличию слова «не»: фраза «перезагрузил —
не помогло» по-прежнему означает выполненное действие. Семантика подтверждения и
отрицания остаётся задачей извлечения. Старые состояния не закрываются массово.

## Запуск без GPU

Все команды из корня репозитория, в подготовленном Python-окружении. На этом Mac
доступен также интерпретатор соседней копии: `../MWS/.venv/bin/python` вместо `python`.

```bash
python src/postprocess_dates.py --input data/organizer/val.jsonl --pred out/json-constrained-4090-baseline-001-full-001/predictions.jsonl --output-dir out/time-calendar-001
python src/compare_temporal.py --gold data/organizer/val.jsonl --before out/json-constrained-4090-baseline-001-full-001/predictions.jsonl --after out/time-calendar-001/predictions.jsonl --output-dir out/time-calendar-001-comparison
```

Имена результатов должны быть новыми. Результат:

```text
out/time-calendar-001/
  predictions.jsonl  # копия предсказаний с разрешёнными правками
  audit.jsonl        # решения по фактам, свидетельства, старое/новое значение
  manifest.json     # режим, счётчики, время, хеши данных и исходников
out/time-calendar-001-comparison/
  comparison.json       # официальные метрики до/после и переходы
  changed-matches.jsonl # изменённые сопоставленные факты: исправлен/испорчен/ещё неверен
```

`--input` может быть выданным JSONL с разметкой, но на границе вызывается `as_call`:
до правил доходят только поля `CallInput`, без эталонных фактов. Оценка читает gold
отдельной командой. Правила не получают путь к gold и не выбирают правки по нему.

Независимые дополнительные операции, которые следует оценивать отдельно:

```bash
python src/postprocess_dates.py --input data/organizer/val.jsonl --pred out/json-constrained-4090-baseline-001-full-001/predictions.jsonl --output-dir out/catalog-001 --mode off --catalog case_data/catalog.json
python src/postprocess_dates.py --input data/organizer/val.jsonl --pred out/json-constrained-4090-baseline-001-full-001/predictions.jsonl --output-dir out/dedup-001 --mode off --deduplicate --speaker-from-source
```

После изменения каталога, говорящего или количества фактов используйте обычный
`src/eval.py`, а не сравнение, которое требует изменения только дат.

## Подключение к инференсу

Новые операции **выключены по умолчанию**. Для явного эксперимента на Linux/macOS:

```bash
export TEMPORAL_NORMALIZATION=conservative
# Необязательно, отдельный эксперимент:
export CATALOG_PATH=data/organizer/catalog.json
```

В PowerShell: `$env:TEMPORAL_NORMALIZATION = "conservative"`.
После этого запустите обычный benchmark с существующей merged-моделью в новый
каталог. `report.json` сохраняет режим и хеш каталога, а `calls.jsonl` —
`temporal_decisions` и числовые счётчики нормализации. Это рекомендуемый путь
проверки на сервере с журналом; обычный HTTP-ответ сохраняет прежнюю схему фактов.

Восстановление невозможной даты выполняется до строгой проверки `Facts`; если
однозначных свидетельств нет, остаётся прежняя обработка некорректных дат.
Для отключения: `TEMPORAL_NORMALIZATION=off`, удалить/обнулить `CATALOG_PATH`.
