# Объединение с organizer-v21-state-accuracy

Проверена ветка `origin/codex/organizer-v21-state-accuracy`, коммит
`9cb2e93728c643536d4f9ba0801d29cbc136f328`. Основа — наша реализация перехода на 2.1.
Изменения интегрированы в текущие локальные файлы; Git-ветки, коммиты и сервер
не менялись этим этапом.

## Что перенесено и улучшено

| Идея ветки | Объединённая реализация |
|---|---|
| `case_v2`: отдельные правила для каталожных и свободных формулировок, симптомов, статусов, договорённостей | Новый режим в общей цепочке нормализации, совместимый с нашей ограниченной историей. Добавлены защита при нескольких объектах, подтверждение вопроса о визите и согласование журнала с финальным интервалом. Каталог кешируется с учётом изменения файла. |
| Восстановление текущего тарифа/статуса, пропущенного моделью | Один `fact_recovery.py`: привязка к своему объекту, отказ при отрицаниях, неоднозначности, вопросах и планах. Не заменяет уже предсказанный текущий положительный факт. Имена объектов не придумываются. |
| Восстановление названия из каталога | Самое длинное полное совпадение; `Орбита-Люкс` не превращается в `Люкс`, `Экстра+` отличается от `Экстра`, упоминание «мини-приставки» не превращается в тариф `Мини`. |
| Подготовка внешнего и вложенного ZIP, проверка CHECKSUMS | Перенесено в существующий `prepare_case.py --archive`. Отдельный дублирующий `prepare_v21.py` не используется. Повреждённый/неизвестный пакет отклоняется до копирования. |
| Сохранение каталога рядом с шумным val | Каталог переносится побайтно; отличный существующий каталог вызывает ошибку. Хеш записывается в манифест. |
| Общий путь к данным | Сохранён `CASE_DATA_DIR`; путь по умолчанию абсолютный. `ORGANIZER_DIR` поддержан как совместимый псевдоним. |

Сохранены наши сильные стороны: два побайтно закреплённых оценщика вместо замены
старого файла новым; обязательное поле имени с допустимой пустой строкой;
явная совместимость старых адаптеров; FP16 для V100; ограниченная память по
клиенту/заявке/сессии; история, применяемая внутри измеряемого времени;
журналы исходных ответов, повторов и ошибок; вывод `Completed N/383; failed: K`.

**Алгоритм обучения не менялся:** один QLoRA `train.py`, тот же способ вычисления
loss и работы с адаптерами. Даты, история, XGrammar и восстановление фактов
работают при генерации ответов, а не при расчёте teacher-forced loss. Параметры
этих будущих проверок отдельно сохраняются в журнале обучения. Переход на новую
разметку и контроль её целостности полезны для следующего цикла; новой эпохи на
этом этапе не было.

## Контрольный результат на второй модели

Это повторная обработка **сохранённых исходных генераций** `continue-002-full-val-003`
на CPU по новому оценщику. Восстановление запускается после календаря и до
истории, в том же порядке, что в рабочем backend. Gold не передаётся правилам.
В новом val изменились входы 24 звонков; полный набор ниже — диагностика, а не
новый end-to-end прогон модели. Отдельно посчитаны 359 звонков с неизменными входами.

| Метрика | Наш прежний task + история | Объединённый вариант | Изменение |
|---|---:|---:|---:|
| fact_precision | 0.4789 | 0.4789 | +0.00 п.п. |
| fact_recall | 0.4921 | 0.5111 | +1.90 п.п. |
| temporal_recall | 0.4081 | 0.4675 | +5.94 п.п. |
| state_accuracy | 0.4270 | 0.4767 | +4.97 п.п. |
| grounding_turn | 0.7137 | 0.7137 | +0.00 п.п. |

Новых фактов добавлено 73; совпавших фактов стало 943 вместо 908. Валидность
сохранённого результата — 1.0. Знаменатель `n_temporal` изменился с 566 до 584:
рост этой метрики нельзя целиком трактовать как исправление дат тех же фактов.

Исходные правила друзей с нашей историей на этих же генерациях дали

P **0.4738**, R **0.5203**,

Наши ограничения дают меньший выигрыш по T/S на этом val, зато исключают
воспроизведённые ложные срабатывания и сохраняют precision/grounding исходной
модели. Непроверенный свободный режим восстановления в рабочий код не добавлен.

Полная локальная обработка правил и истории заняла около
**15.03 мс/звонок**,
без модели, оценщика и GPU. Это не замер GPU-секунд или памяти V100 и не точка
ресурсной кривой. Прирост ресурсоёмкости генерации предстоит измерить на сервере.

Цели новой базы: T ≥0.4506, S ≥0.5145. На этом контрольном пересчёте время выше
цели на 1.69 п.п., состояния ниже цели на
3.78 п.п. Запас для скрытого/шумного теста не
подтверждён; качество состояний остаётся следующей задачей. Числа модели 003/004
из документов ветки не присваиваются нашей второй модели.

## Запуски и журналирование

По умолчанию `FACT_RECOVERY=0`, режим дат `task`: старый запуск не переключается
молча. Для новой проверки подготовлен явный preset `case_v2` + `FACT_RECOVERY=1`
+ наша история и XGrammar в единственном актуальном сценарии
`docs/evaluations/continue-002-v21/run_full_val.py`.

В `report.json`, прямом predict и `/health` видны режим восстановления и его
политика; в отчёте есть хеш каталога дат. Изменения каждого добавленного факта
попадают в аудит с объектом и источником. Сравнение ресурсов отклоняет разные
режимы восстановления/календаря/каталога. Для Docker каталог монтируется отдельно,
без копирования прежнего `case_data` в образ.

Команды и ограничения общего сервера: [CASE_V21_MIGRATION.md](CASE_V21_MIGRATION.md).
Комплект обновлён до **case-v21-002**; 001 не включает эту интеграцию. При занятых
22 GiB запускать проверку пока не нужно: для preset требуется 14 GiB свободно.

## Подготовка к мёрджу

Подготовлен `outputs/organizer-v21-unified.patch`: преобразует точный коммит
`9cb2e93728c643536d4f9ba0801d29cbc136f328` в объединённый runtime. Его не надо
повторно применять к текущим файлам — здесь интеграция уже выполнена. Патч нужен
для ветки друзей. Он сохраняет их дополнительные документы вне изменяемой области;
снимки прошлых экспериментов и сырые результаты не подменяются.

В патче остаются одна подготовка данных, один train, одна цепочка оценки и один
актуальный сценарий новой проверки. `src/prepare_v21.py` удаляется, поскольку его
возможности перенесены в `prepare_case.py`; тесты переведены на общий интерфейс.
Перед применением нужны чистая рабочая папка и проверка точного коммита. Проверка
применения и тесты выполняются на локальной копии, без GitHub и без изменения
текущей ветки. Инструкция лежит рядом с патчем.

Локальные доказательства: [CPU-проверка данных](experiments/4090-continue-002/evaluations/full-val-v21-002/cpu-verification.json),
[метрики A/B](experiments/4090-continue-002/evaluations/full-val-v21-002/rule-ab-comparison.json).
Пять проверок с настоящими ML-зависимостями локально пропускаются и запускаются
серверным preflight. Docker-образ и новая GPU-генерация здесь не запускались.
