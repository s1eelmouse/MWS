# Проверки и доказательства для защиты

Ветка `feat/defense-evidence-suite` основана на `fix/current-tariff-service-recovery`.
Веса, обучение, правила извлечения и официальные оценщики не изменены.

## Что уже сделано локально

Один инструмент `src/defense_evidence.py` проверяет правила, заново обрабатывает
одинаковые сырые ответы в трёх режимах и строит автономную HTML-страницу.
Никаких API, новых генераций или передач gold правилам нет.

Полный val 2.1: 383 звонка, 1 845 эталонных фактов, официальный оценщик 2.1 без
исправлений. Контрольный режим воспроизвёл все исходные серверные факты.

| Восстановление фактов | Precision | Recall | Temporal | State | Grounding |
|---|---:|---:|---:|---:|---:|
| Выключено | 50,00% | 49,86% | 46,88% | 43,18% | 71,41% |
| Прежние правила, v1 | 50,10% | 51,98% | 48,37% | 49,12% | 71,43% |
| Новые правила, v2 | 49,55% | 53,66% | 49,00% | 53,45% | 71,11% |

Обработка дат `case_v2` включена во всех трёх режимах. «Выключено» означает
выключение восстановления фактов, а не календаря или constrained decoding.
Это абляция качества правил, **не кривая ресурсов GPU**. CPU-время обработки
сохранено отдельно; его нельзя выдавать за время инференса нейросети.
Val использовался в разработке, поэтому это не результат на скрытом тесте.

Во всех режимах: 100% валидного формата, нет пропущенных/отказавших звонков и
структурно неверных источников. Это не означает 100% смысловой точности источника.

## Сложные проверки

89 существующих синтетических тестов календаря, привязки дат, интервалов и
текущих состояний собраны в машиночитаемый отчёт; все пройдены. Покрываются
вопросы без подтверждения, отрицание, будущее/прошлое, неоднозначные объекты,
похожие названия, коррекция тарифа, ASR-варианты и границы интервалов.
Полный набор проекта: **308 тестов, OK, один skip — локально нет XGrammar**.

Это проверки детерминированных компонентов. Устойчивость полной модели на
adversarial-подмножестве ими не доказана. Для такого утверждения потребуется
отдельный прогон генерации на утверждённом сложном наборе; не следует называть
ручные синтетические тесты официальным adversarial-набором организаторов.

В одном старом тесте переноса модели исправлено сравнение путей: macOS `/var`
и `/private/var` могут вести к одному файлу. Теперь сравниваются разрешённые
пути. Требования к содержимому передаваемых весов/данных не ослаблены.

## Как получить отчёт и открыть демо

Запуск из корня репозитория, в окружении проекта. Указать свои пути;
каталог результатов должен быть новым.

```bash
python src/defense_evidence.py \
  --gold /path/to/organizer-v2.1/val.jsonl \
  --catalog /path/to/organizer-v2.1/catalog.json \
  --raw /path/to/4090-003-datefix-full-001/raw-answers.jsonl \
  --reference-pred /path/to/4090-003-datefix-full-001/predictions.jsonl \
  --output-dir out/defense-evidence-new
```

- `report.json`: агрегаты, ошибки по атрибутам, результаты тестов, хеши входов/кода.
- `off/v1/v2-predictions.jsonl`: предсказания каждого режима.
- `evidence-private.json`: изменённые/добавленные факты, цитаты и решения правил.
- `index.html`: открыть обычным браузером, сервер и сеть не нужны.

Демо показывает факт, его прежний вариант (если был), цитату, границы времени
и журнал правил. Сам факт изменения ещё не означает исправление: среди
добавлений есть ложные, что отражено снижением precision. Журнал правил —
объяснение детерминированной обработки, а не внутренних рассуждений модели.
HTML экранирует текст и запрещает скрипты/внешние ресурсы.
Подробный отчёт содержит данные звонков: хранить локально, перед показом жюри
обезличить имена, идентификаторы и другие персональные сведения.
В GitHub публикуются только код и агрегаты, не транскрипты и предсказания.

## Готовый запуск замеров GPU

`src/resource_matrix.py` планирует три полных запуска на одном GPU с одинаковыми
весами, данными, оценщиком, календарём, recovery, лимитами и warmup.
Меняется только batch size: **1 / 2 / 4**. FP16 — текущий режим backend;
переключателя 4-bit инференса в нём нет, результаты такой конфигурации не придуманы.

Сначала посмотреть план (ничего не запускает и не создаёт):

```bash
python src/resource_matrix.py \
  --model /path/to/installed-merged-model \
  --gold /path/to/organizer-v2.1/val.jsonl \
  --output-dir out/defense-matrix-new
```

На сервере из tmux выполнить ту же команду с `--execute`. Нужны уже установленные
локальные веса и каталог рядом с val. Загрузка с Hugging Face отключена.
Скрипт проверяет CUDA, не перезаписывает старые результаты, сохраняет журнал
каждого запуска и при ошибке останавливает оставшиеся. Это инференс, не обучение.
Ветка и окружение должны оставаться одинаковыми для всех запусков.

После трёх успешных измерений:

```bash
python src/compare_runs.py \
  --reports out/defense-matrix-new/batch-1/report.json \
            out/defense-matrix-new/batch-2/report.json \
            out/defense-matrix-new/batch-4/report.json \
  --gold /path/to/organizer-v2.1/val.jsonl \
  --baseline-pred /path/to/organizer-v2.1/baseline_pred.jsonl \
  --output-dir out/defense-resource-comparison-new
```

Существующий сравниватель проверит совместимость и создаст CSV/JSON/SVG.
При отказе совместимости не обходить проверку и не объединять несовместимые точки.
В частности, аппаратный снимок `nvidia_smi` должен удовлетворять его проверкам.
OOM/ошибки/неполные запуски сохранять как ограничения, а не успешные точки.

Замеры GPU здесь ещё не выполнены. Ускорение относительно учителя ≥5× не доказано:
нужно сопоставимое измерение учителя. Сокращение параметров ≥10× также требует
подтверждённого размера именно baseline-модели; нашей компактной модели около 596 млн.
