# Сдача выбранной Qwen3-0.6B: 005

Основной путь сдачи — Transformers, объединённые веса
`merged-4090-continue-005-noise-001`, FP16. Нового обучения этот пакет не запускает.
Исторические таблицы 001–003 и экспериментальный vLLM не являются инструкцией
запуска выбранной версии. Полный SHA256 весов закреплён в `src/release_profile.py`.

## Подтверждённое качество

383 звонка нового val, оценщик 2.1 без datefix: P 53,19%, R 58,32%,
T 49,00%, S 55,22%, G 78,44%, 0 отказов, 100% формата.
Это опубликованный GPU-прогон, а не новые измерения этой ветки.
Отчёт: `docs/experiments/4090-continue-005-noise/attachments/full-val/report.json`.
Пороги T≥45,06%, S≥51,45% пройдены на clean val; скрытый тест этим не доказан.

## Что исправлено для воспроизведения

- Сервис Compose выбирает 005, `case_v2`, recovery и историю, как в отчёте.
- Сценарий старого эксперимента явно задаёт режимы и сам готовит noisy-вход.
  Замороженный измеренный код и его manifest не менялись.
- Clean, noisy и ресурсная матрица используют общий профиль, независимо от
  посторонних настроек терминала. Перед исполнением проверяются хеши весов,
  нового val/каталога и совместимость контракта 2.1.
- Сравнение ресурсов отклоняет разные хеши правил даже при одинаковом имени
  политики. Так разные реализации recovery v2 не смешиваются незаметно.
- Исправлено сравнение эквивалентных временных путей macOS в тесте переноса.

## Запуски на GPU-сервере

Команды выполнять в корне этой ветки, в установленном окружении проекта.
Существующие веса и результаты не перезаписываются. В примерах заменить пути
на фактические; `catalog.json` должен лежать рядом с `val.jsonl`.

Сначала посмотреть план: без GPU, загрузок модели и создания результатов:

```bash
python src/release_validate.py --mode noisy \
  --model /home/ubuntu/mws/out/merged-4090-continue-005-noise-001 \
  --gold /home/ubuntu/mws/data/organizer_v2_1/val.jsonl \
  --output-dir out/release-005-noisy-new
```

Для выполнения добавить `--execute`. Запускать из tmux. Он создаст шумный val
с level=0.15/seed=42 и выполнит полный benchmark; обучение не вызывается.
Отчёт: `out/release-005-noisy-new/benchmark/report.json`.
`--mode clean` проверит чистый val; `--device cpu` — отдельный CPU-прогон.
CPU сначала проверить на время вручную: полный набор может занять долго.

Три совместимые GPU-точки одной модели, batch 1/2/4:

```bash
python src/resource_matrix.py \
  --model /home/ubuntu/mws/out/merged-4090-continue-005-noise-001 \
  --gold /home/ubuntu/mws/data/organizer_v2_1/val.jsonl \
  --output-dir out/release-005-matrix-new --execute
```

Каждый режим стартует отдельным процессом с одинаковым конфигом. При ошибке
оставшиеся режимы останавливаются, сделанные результаты сохраняются.
Нельзя незаметно уменьшать batch после OOM и считать результат исходной точкой.

Построить таблицы и кривую после трёх успешных запусков:

```bash
python src/compare_runs.py \
  --reports out/release-005-matrix-new/batch-1/report.json \
            out/release-005-matrix-new/batch-2/report.json \
            out/release-005-matrix-new/batch-4/report.json \
  --gold /home/ubuntu/mws/data/organizer_v2_1/val.jsonl \
  --baseline-pred /home/ubuntu/mws/data/organizer_v2_1/baseline_pred.jsonl \
  --output-dir out/release-005-curve-new
```

## Сервис

Указать `MODEL_PATH` и `CATALOG_FILE`, затем использовать обычный
`docker compose -f docker-compose.yml -f docker-compose.gpu.yml up --build`.
Для передачи жюри проверить `/health`, `/extract` и `/extract_batch` на реальных
005-весах с новым каталогом. Бинарные веса в Git/образ не добавляются.
До загрузки сервиса можно выполнить `release_validate.py --mode clean --execute`
для полной проверки идентичности весов/данных. Docker-образ этой ветки локально
не собран: Docker CLI на ноутбуке отсутствует. GPU/HTTP-успехи не заявляются заранее.

## Что осталось измерить и показать

1. Результат noisy 005, включая ошибки по атрибутам и размер временного знаменателя.
   Синтетический шум может удалять смысловые слова: это локальный стресс,
   не официальный adversarial-набор.
2. Три ресурсные точки и CPU-замер. Время 7,07 с/звонок в старом отчёте — среднее
   амортизированное; фактическая готовность ответа batch2 p50/p95 — 14,33/18,38 с.
3. Ускорение ≥5×. По сообщённому командой ответу ментора сравнение допускается с
   моделью около 1.5B. Измерить на том же железе, с теми же данными/декодированием,
   одинаковым batch, без преимущества за счёт пустых/ошибочных ответов.
   Сравнительная модель не заменяет выбранную 0.6B. 5× пока не доказаны.
4. Скачать новые веса, адаптер и полные результаты 005 с проверкой SHA256.
   Старый архив 003 не является бэкапом 005.
