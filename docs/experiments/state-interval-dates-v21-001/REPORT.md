# Исправление дат состояний: 15 ноября 2026

Ветка: `fix/state-interval-dates-v21`, основа актуального `main` — `b2cfc1b`.
Коммиты кода: `18b80df` (тарифы/услуги), `652a9c4` (статусы и защита от чужих дат).
Модель остаётся Qwen3-0.6B. Обучение и генерация новых ответов не выполнялись.

## Нужны ли сервер и обучение

Для этой работы сервер не требовался: правила проверены на ноутбуке по
сохранённым ответам из `artifacts-4090.tar.zst`. Следующий GPU-шаг — свежий полный
прогон имеющихся весов на новом val с новыми правилами. Использовать доступную
университетскую V100; арендовать отдельный сервер имеет смысл, если университетский
недоступен или очередь мешает работе. Покупка/аренда не является условием продолжения
анализа дат.

Новое обучение не запускать автоматически. Если после свежего прогона остаются
пропуски/неверные значения услуг и тарифов, потребуется отдельный эксперимент
обучения на обновлённом train. Эти ошибки не исправляются одним календарём.

## Что изменено

Изменения действуют в существующем режиме **`case_v2`**. Режим по умолчанию не
переключался; для сервера его необходимо задать явно. Остальные режимы, правила
договорённостей, веса и память между звонками не изменялись.

### Тарифы и услуги

- Добавлена привязка явного подключения/перехода и окончания тарифа к названному
  значению. «Вчера перешла с Пульса на Смарт» закрывает старый тариф и задаёт начало
  нового; просмотр тарифа, предложение или вопрос этого не делают.
- Начало и конец интервала применяются вместе с проверкой порядка. Неназванная
  историческая граница сохраняется; неизвестная дата не угадывается.
- Для услуг различаются «со вторника нет гудков», «нет гудков было до вчера» и
  «ещё вчера работало нормально». Последняя фраза сама по себе не задаёт конец
  нормального состояния.
- Закрытое состояние не открывается из-за даты соседнего действия/заявки.
  Открытие разрешено при явном продолжающемся симптоме. Разнесённая по фразам дата
  используется, если в контексте назван тот же симптом и есть указание на начало.
- Конкурирующие значения, неоднозначные даты, отрицание, гипотеза и вопрос ведут
  к отказу от изменения. Часовой пояс сохраняется; тариф с `+` отличается от
  одноимённого тарифа без `+`.
- «Месяц назад» и другие неточные периоды не превращаются в произвольный день.

### Статусы заявок

- Явные границы ищутся в пределах текущего звонка для **той же пронумерованной
  заявки**. Ненумерованная реплика допускается только при одной известной заявке
  в транскрипте. Между аккаунтами и звонками этот код ничего не переносит.
- «До вчера была принята, а сейчас в работе» позволяет согласовать конец старого
  и начало нового статуса. Противоречащие друг другу даты не разрешаются выбором
  первой/последней реплики.
- Дата визита мастера или контрольного звонка не используется как дата статуса.
- Цепочка не достраивается по порядку статусов и произвольным датам модели.
  Старый параметр `close_chains` остаётся выключенным по умолчанию.

Добавлены модули `src/state_intervals.py`, `src/ticket_intervals.py` и 26
проверок семантических границ в `tests/test_state_intervals.py`. Хеши новых модулей
включены в манифест пакетной обработки. В runtime передаются только `CallInput`,
предсказанные факты и каталог; gold доступен только оценке после обработки.

## Как повторить без GPU

Из корня репозитория, с установленными CPU-зависимостями; подставить путь к
сохранённому `003-module-recovery.jsonl`. Каталог нового пакета нужен явно.
Выходная папка должна быть новой:

```bash
python docs/experiments/state-interval-dates-v21-001/compare.py \
  --gold data/organizer-v2.1/val.jsonl \
  --catalog data/organizer-v2.1/catalog.json \
  --pred /path/to/artifacts-4090/003-module-recovery.jsonl \
  --output-dir out/state-interval-ab-new
```

Скрипт берёт старый календарь через `git show b2cfc1b`, не меняя рабочую ветку,
сохраняет оба набора предсказаний, результаты, хеши и пары улучшений/регрессий.
Зависимости старого слоя в этой ветке не менялись; новые модули вызываются только
новым календарём. Скрипт проверяет неизменность остальных полей и идемпотентность.

## Что делать сокоманднику на сервере

1. Получить отдельную ветку `fix/state-interval-dates-v21`. Не заменять ей `main`
   автоматически; сначала проверить на своих свежих ответах V100 и сравнить.
2. Сохранить веса, настройки и текущие результаты. Для анализа использовать новые
   входы пакета 2.1, старые оставить нетронутыми.
3. Для следующего запуска явно выставить:

```bash
export TEMPORAL_NORMALIZATION=case_v2
export TEMPORAL_CATALOG_PATH=data/organizer-v2.1/catalog.json
export CATALOG_PATH=data/organizer-v2.1/catalog.json
export SCORER_VERSION=2.1
export SAVE_RAW_RESPONSES=1
export JSON_GRAMMAR_BACKEND=torch_native
```

4. Взять те же merged-веса 003 и те же настройки recovery/истории, что у контроля.
   Сделать короткую проверку, длинный пример, затем все 383 новых входа. Сохранить
   полную сырую генерацию, предсказания, настройки, время и память. Новый каталог,
   recovery и память не переключать одновременно с календарём без отдельного A/B.
5. Проверить, сохранился ли прирост времени и нет ли потерь текущих состояний.
   Отдельно разобрать пропуски услуг и выбор текущего тарифа: это следующие задачи,
   которые не закрывает перенос дат.
6. Решать про новый цикл обучения только после свежей оценки. При смене train —
   новая папка эксперимента и старт от сохранённого адаптера, а не подмена данных
   при resume старого запуска. Модель остаётся Qwen3-0.6B.

Новые GPU-замеры, фактическая работа этой ветки на V100 и прохождение скрытого
теста пока не подтверждены. Код и синтетические проверки не гарантируют отсутствие
новых ошибок на других транскриптах.
