## Повтор и оценка

[replay.sh](replay.sh) — новый вспомогательный сценарий на основе зафиксированных
команд, не исторический файл. Он вызывает исходники именно из code, а данные/out
берёт из рабочего проекта. Использует новые имена RUN_ID, существующие результаты не заменяет.
Для этого первого цикла исторический bash-файл не сохранился.
Для первого исторического bash-файла нет: команда обучения записана в приложениях.

В Linux активировать соответствующее окружение и подготовить data/organizer;
для второго цикла нужен исходный адаптер первого. Из корня проекта:

```bash
RUN_ID=4090-baseline-001-replay-001 bash docs/experiments/4090-baseline-001/replay.sh test
RUN_ID=4090-baseline-001-replay-001 bash docs/experiments/4090-baseline-001/replay.sh all
```

test — программные тесты и компиляция, без обучения.
all — обучение, merge и самостоятельная генерация на полном val с официальной оценкой.
train — только обучение; evaluate — merge и оценка уже полученного out/$RUN_ID.
Для all и test разные логи. При повторении той же команды выбрать новый RUN_ID.
PROJECT_DIR позволяет указать серверный рабочий каталог с данными и out.
Во втором цикле INIT_ADAPTER_DIR позволяет явно задать сохранённый исходный адаптер.
Проверка GPU и длительность здесь не заявлены: новые replay-сценарии не выполнялись.
Не менять архивный code при разработке новых циклов. Развивать общий src/tests,
а для следующего эксперимента делать новый снимок и новый реестр.
