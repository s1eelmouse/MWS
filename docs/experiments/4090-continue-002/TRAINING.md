# Алгоритм второго цикла: 4090-continue-002

Фактически выполнен 14.11.2026 на RTX 4090. Исполняемый сценарий:
[run-continue-002.sh](run-continue-002.sh).
Это копия сценария из скачанного серверного комплекта, а не восстановление по памяти.

## Чем этот цикл отличается от первого

Начальная модель: Qwen/Qwen3-0.6B с уже обученным адаптером первого цикла
`out/4090-baseline-001`. Обучается существующий адаптер; второй новый LoRA поверх
первого не создаётся. Базовые веса заморожены после подготовки к QLoRA.

Оптимизатор и cosine-расписание создаются заново. Состояние оптимизатора первого
цикла не загружается. Это `--init-adapter-dir`, а не `--resume-from-checkpoint`.
Последний нужен для восстановления прерванного запуска, а не для нового цикла.

Первая модель прошла одну эпоху; здесь выполнен ещё один полный проход train.
Второй цикл одновременно меняет число проходов, learning rate и состояние
оптимизатора, поэтому его нельзя описывать как чистую абляцию только числа эпох.

## Последовательность сценария

1. Перейти в `/home/ubuntu/mws-measurements-002`, активировать
   `/home/ubuntu/mws/.venv` и задать переменные окружения.
2. Проверить, что каталоги нового адаптера, merged-модели, benchmark и общий лог
   отсутствуют. Если любой путь существует — остановиться, не перезаписывать результат.
3. Включить общий stdout/stderr-лог через tee и остановку цепочки при ошибках.
4. Проверить исходный адаптер: базовую модель, LoRA, подпись контракта, веса и
   разделение исходного/выходного каталогов; записать SHA256 исходных файлов.
5. Подготовить train/val без обрезания и пересечения аккаунтов. Загрузить базовую
   модель в 4 битах и существующий адаптер через PeftModel.from_pretrained с
   is_trainable=True. Создать новый Trainer, оптимизатор и расписание.
6. Обучить адаптер одну эпоху; сохранить итоговые веса, tokenizer, checkpoints,
   параметры, окружение, события loss/памяти и итоговые ресурсные замеры.
7. Загрузить базовую модель в FP16, объединить новый адаптер и сохранить в новый каталог.
8. На всех 383 звонках val выполнить benchmark: batch2, один прогревочный batch,
   самостоятельная генерация без gold. Сохранить официальное качество, задержки,
   память, длины и raw-ответы при отказах. XGrammar в этом прогоне не применялся.
9. После успешного окончания вывести `DONE: training, merge and full-val benchmark complete`.

## Команды, которые выполнялись

Полный набор export и проверок находится в сценарии. Основная цепочка:

```bash
python -u src/train.py --init-adapter-dir out/4090-baseline-001 \
  --learning-rate 0.0001 --epochs 1 --batch-size 1 --seed 42 --save-steps 50 \
  --output-dir out/4090-continue-002

python -u src/merge.py --adapter-dir out/4090-continue-002 \
  --output out/merged-4090-continue-002

python -u src/benchmark.py --input data/organizer/val.jsonl \
  --model out/merged-4090-continue-002 --device cuda --batch-size 2 \
  --output-dir out/benchmark-4090-continue-002
```

При отдельном ручном выполнении следующую команду запускать только после успеха
предыдущей. Готовый bash-сценарий обеспечивает это через `set -euo pipefail`.

## Как запускать сценарий из репозитория

На Linux после переноса кода в исходную серверную папку:

```bash
tmux new-session -d -s mws-cycle-002 \
  'bash /home/ubuntu/mws-measurements-002/docs/experiments/4090-continue-002/run-continue-002.sh'
```

Исторически сценарий лежал в корне серверного проекта; в Git он помещён рядом с документацией этого цикла, в docs/experiments/4090-continue-002.
Внутри сценария пути к коду и .venv абсолютные и соответствуют нашему серверу.
На другой машине их нужно заменить.

**Выполненный 002 повторно не запускать с теми же путями.** Для повторения скопировать
сценарий и задать новые имена четырём выходам: adapter, merged, benchmark, log.
Старый исходный адаптер оставить прежним, если требуется повтор именно этого опыта.
Это не автоматический запуск третьего цикла с весов второго.

## Результат и границы воспроизведения

Обучение завершилось за 2012.87 с, eval_loss=0.13454. В исходном экспорте новой
модели 347 из 383 ответов отказали, преимущественно из-за JSON. Поэтому сценарий
фиксирует проведённый эксперимент, а не рекомендует его модель как финальное решение.
Локальная исследовательская реконструкция JSON выполнялась отдельно и в сценарий не входит.

Сценарий не устанавливает зависимости и не скачивает датасет. Нужны исходный адаптер,
исходные данные, проверенное окружение и доступная база Qwen соответствующей revision.
Снимки окружения/кода находятся в результатах. Seed не гарантирует побитного совпадения
при другой платформе или версиях библиотек. Веса и результаты в Git не добавлять.
