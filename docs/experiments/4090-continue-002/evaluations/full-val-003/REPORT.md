## Проверка сохранения и воспроизводимости

Архив и распакованные файлы побайтно совпали: проверены все 18 файлов архива.
64 файла исходников/настроек совпали с реестром переносимого кода. Веса проверялись
preflight по хешу объединённой модели второго цикла. Проверены 383 уникальных call_id,
383 сырые генерации и завершение DONE в общем логе. Официальные метрики заново
пересчитаны локально по итоговым предсказаниям и совпали с серверными полностью.

Включены XGrammar 0.2.9, backend torch_native, Facts schema, task-нормализация дат,
нормализация каталога, speaker по источнику, точная дедупликация, повтор при лимите
токенов с penalty 1.2. Повторов фактически 0. Бюджеты 12288/16384/4096; greedy,
thinking выключен, одна RTX 4090, FP16, batch2, 8 CPU threads, один прогрев.
Полный валидатор и postprocess получают входные звонки без gold; эталоны используются оценщиком.

## Условия качества

На этом val временная полнота .4237 выше пересчитанного baseline .4205 на .0032,
state .3852 выше .3194 на .0658. Относительно опубликованных .4161/.3483 показатели
также выше. Ограничения падения на известном val выполнены; формат корректен на 100%.
Это не подтверждение скрытого теста и не всей готовности к сдаче: ещё нужны ресурсная
кривая, сравнение GPU-секунд с разрешённой более крупной моделью, CPU и проверка сервиса.

## Что дала финальная обработка серий

[Сравнение на тех же фактах](attachments/series-date-comparison/comparison.json):
temporal .4000 → .4237. Из 760 сопоставленных фактов 304 уже имели верные даты,
18 исправлены, 438 остались неверными. Изменены даты у 36 сопоставленных фактов;
регрессий правильное → неправильное не обнаружено. Остальные метрики не менялись.
Счётчик series_accepted_carried=37; он считает операции, не число правильно исправленных фактов.

Это НЕ сравнение полного режима dates off/on: до финальной стадии уже работали
XGrammar, нормализация внутри звонков и каталога. Внутризвонковый журнал фиксирует
489 изменений полей дат, 53 удаления точных дублей, 8 нормализаций каталога,
11 сброшенных невозможных дат, 3 исправления speaker и 2 открытия обратных интервалов.
Число исправлений формата не равно числу семантически правильных исправлений.

Финальная серия использует несколько звонков одного account_id в порядке series.
HTTP-путь с отдельными независимыми запросами не получает этот эффект автоматически.
Для той же семантики на демо/сдаче нужен согласованный интерфейс пакетной обработки
или состояние по аккаунту с проверкой порядка и отсутствия смешения аккаунтов.
Без финальной серии в этом запуске temporal=.4000: это чуть ниже цели .4005 по
пересчитанному baseline, хотя выше .3961 по опубликованному. Различие нужно раскрывать.

Сильнее всего статусы заявок. Договорённости дают 850 из 1136 несовпавших предсказаний
(74.82%): приоритетны неподтверждённые предложения, дубли по смыслу и неверный объект.

основной слабостью; часть исторических начал в gold может не выводиться из текста.

## Следующие шаги

1. Зафиксировать эту версию как рабочую контрольную. Исторические модели/результаты не менять.
2. Проверить идентичность обработки дат в benchmark и HTTP/демо, в особенности серию аккаунта.
3. Получить три ресурсные точки: текущая GPU batch2, затем GPU batch1/4 с теми же
   компонентами и полным val. Дополнительно CPU pilot и согласованный CPU-замер.
4. Отдельно измерить разрешённую модель около 1.5B на том же GPU и одинаковом batch,
   данных, лимитах, схеме и правилах. Пока числа ускорения нет.
5. На выборке ошибок разобрать agreement, пропущенные действия и состояния.
   Любой фильтр проверить по precision И recall на полном val, не по паре удачных примеров.
6. Даты улучшать абляциями правил по атрибутам, сохраняя исправления/регрессии.
   Следующую эпоху без изменения гипотезы сейчас запускать не приоритетно.
