# Серверная проверка интервалов и статусов: 4090-v21-status-001

15.11.2026. Полный новый официальный val 2.1, 383 звонка; RTX 4090,
Qwen3-0.6B после дообучения на train 2.1 (`4090-continue-v21-001`).
Релиз обработки — `case-v21-status-001`. Обучения и изменения весов в этом
эксперименте не было. Это завершённый непрерывный GPU-прогон, а не CPU-replay.

## Основной результат

**383/383 звонка, 0 отказов, валидность JSON/схемы 100%, некорректных ссылок
на реплики нет.** Все пять метрик, все итоговые предсказания и предсказания
до истории полностью совпали с предварительной локальной проверкой.

| Метрика | Исходный серверный прогон | Новый серверный прогон | Разница |
|---|---:|---:|---:|
| Fact precision | 50.93% | **51.26%** | +0.33 п.п. |
| Fact recall | 53.44% | **54.09%** | +0.65 п.п. |
| Temporal recall | 48.59% | **50.49%** | +1.90 п.п. |
| State accuracy | 50.56% | **52.97%** | +2.41 п.п. |
| Grounding turn | **78.80%** | 78.56% | −0.24 п.п. |

Совпало 998 из 1845 эталонных фактов; всего предсказано 1947. Правильных
состояний 330 из 623 вместо 315. Изолированный вклад статусного слоя относительно
контроля с теми же новыми интервалами — **14 исправлений S без регрессий**.
Ещё одно состояние услуги исправилось благодаря календарной обработке.
Это не утверждение об отсутствии регрессий всех атрибутов/всех метрик.

Все 383 исходных `raw_response` совпали с генерациями предыдущего GPU-прогона.
Таким образом, для этой пары экспериментов прирост качества обусловлен обработкой
одинаковых ответов, а не изменившейся генерацией или дополнительным обучением.

Нельзя обещать прохождение скрытого теста по одному знакомому набору.

## Время и ресурсы — фактический непрерывный замер

| Показатель | Значение |
|---|---:|
| GPU | RTX 4090, 24564 MiB по nvidia-smi |
| Базовых параметров | 596049920 |
| Инференс | merged FP16, batch=2, greedy, XGrammar torch_native |
| Измеренная обработка 383 звонков | **2443.585 с = 40 мин 43.6 с** |
| Весь этап validation | 2473.164 с = 41 мин 13.2 с |
| Сумма этапов tests + validation | 2481.183 с = 41 мин 21.2 с |
| Пропускная способность | **564.25 звонка/час** |
| Амортизированное время | **6.380 с/звонок** |
| Выделенные GPU-секунды на 1000 звонков | **6380.118** |
| Задержка готовности ответа p50 / p95 / max | **12.85 / 16.62 / 20.59 с** |
| Пик CUDA allocated | **4919040000 байт = 4.58 GiB** |
| Пик CUDA reserved | **6280970240 байт = 5.85 GiB** |
| Выборочный пик RSS процесса | **2007584768 байт = 1.87 GiB** |
| Измерений RSS | 48643, целевой интервал 0.05 с |
| Входных / выходных токенов всего | 604950 / 157992 |
| Максимум входа / выхода | 10095 / 791 токен |
| Повторов из-за лимита токенов | **0** |

GPU-секунды здесь означают **одна выделенная GPU × измеренное время обработки**,
а не время выполнения CUDA-ядер и не энергопотребление. Время включает правила
и историю в `backend.extract`, но исключает очередь/сеть/запись файлов; загрузка
модели и прогрев вынесены отдельно. Загрузка 4.315 с, компиляция грамматики
0.503 с, прогрев 9.645 с. Пик CUDA сброшен после прогрева и измерен на всём val.

При batch=2 задержка каждого звонка — время готовности всей его пачки:
**p95 нельзя делить на два**. 6.380 с — амортизированная стоимость, не p95
индивидуального запроса. RSS — память процесса, не вся оперативная память сервера;
CUDA allocated/reserved не равны полной VRAM по nvidia-smi.

В предыдущем восстановленном прогоне активное время было 2776.101 с
(46 мин 16 с, 496.67 звонка/час). Новый прогон короче примерно на 12%, но один
непрерывный и один сегментированный запуск не доказывают ускорение от правил.
Мы не меняли веса или алгоритм генерации; фактические raw-ответы совпали.
Разница времени может зависеть от состояния стенда. Старый полный пик CUDA был
утрачен, поэтому сравнение пиков памяти с ним не выполняется.

Этот результат — полноценная одна точка для будущей кривой «ресурсы × качество».
Для доказательства ускорения относительно разрешённой менторами модели 1.5B
нужен её отдельный сопоставимый замер: те же val, обработка, оборудование,
точность весов, batch, прогрев и определение GPU-секунд. Сейчас такого сравнения
этот эксперимент не содержит. Энергия и реальная загрузка GPU во времени здесь
не измерялись.

## Цена истории и аудит обработки

История занимает максимум **20590 байт сериализованных данных**, в конце хранит
58 записей для 57 аккаунтов. Это размер полезной сериализованной нагрузки,
не полный размер Python-объектов. Её собственный таймер — **0.136 с** на весь
прогон, уже включённые в основное измерение; 30 переносов дат, 6 отказов из-за
конфликта интервалов. Для этого val накладные расходы истории малы.

Recovery: **89 добавлений** (включая прежние тарифы), **2 удаления**,
**12 воздержаний** от неоднозначного изменения. Границы старых подтверждённых
статусов без доказанной даты не выдумывались. Измерения содержат также
165 исправленных полей дат, 42 точных дубликата, 5 отброшенных некорректных
дат, одну исправленную привязку speaker и один раскрытый обратный интервал.
Отсутствие failed не означает отсутствие таких нормализаций: это разные счётчики.

## Что проверено независимо

1. SHA256 архива совпал с серверной суммой; проверены все **19 файлов** архива
   против распакованных байтов, в том числе общий журнал рядом с папкой запуска.
2. Проверены 18 файлов инвентаризации загрузчика. Сохранены исходный архив,
   серверная сумма и первоначальный `download-verification.json`.
3. Манифест релиза совпал с локальным отправленным комплектом, все его файлы и
   хеши исходников из server environment проверены против распакованного релиза.
4. Merged-веса совпали с прежними локальными весами по SHA256; val и каталог
   именно 2.1. Проверен полный порядок всех 383 call_id, 192 пачки, 383 исходных
   ответа/итоговых ответа/записи calls. Последний progress — 383/383, failed=0.
5. Официальный оценщик запущен независимо: весь official-блок совпал точно.
   Валидация источников и повторный расчёт всех per-attribute диагностик тоже совпали.
6. Все предсказания до/после истории совпали с локальным CPU-replay. Все исходные
   генерации совпали с предыдущим GPU-прогоном.
7. Суммы времени пачек, throughput, GPU-секунды, задержки, токены, число измерений
   RSS и его пик пересчитаны из первичных журналов и совпали с report.json.
8. На сервере прошли **все 292 теста**, без пропусков; этапы завершились exit_code=0.

## Дальнейшие действия

1. Сохранить этот релиз как проверенную исходную точку. Повторять тот же прогон
   без изменения гипотезы сейчас не требуется.
2. Следующий небольшой шаг по исходному плану — текущие тарифы: 25/40 расхождений
   связаны с полным пропуском атрибута. Нужны подтверждения между репликами,
   поправки «раньше X, теперь Y», защита от предложенного/отвергнутого тарифа,
   точная канонизация с сохранением `+`, `X`, `XL`. Сначала CPU A/B по сохранённым
   исходным ответам, независимые сценарии/train и регрессии всех метрик.
3. Для большего запаса по S главный резерв — услуги и оборудование: выделение
   жалобы/восстановления и её объекта, одновременные состояния разных каналов.
   Дополнительное обучение имеет смысл только как отдельная проверяемая гипотеза.
4. Отдельно сокращать неподтверждённые договорённости и улучшать источники:
   запас G всего 0.21 п.п. Нельзя улучшать S ценой фактической привязки к чужой заявке.
5. Проверить шумный dev по аккаунтам из train и затем собрать сопоставимую
   ресурсную точку модели 1.5B. Официальный val не использовать для создания
   новых обучающих сценариев по его gold-ответам.
