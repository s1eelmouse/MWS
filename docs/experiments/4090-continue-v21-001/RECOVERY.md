# Восстановление проверки после остановки оплаты

Обучение и merge завершены. По проверке на сервере сохранились model/adapter,
372 полных predictions, predictions-before-series и calls, 186 полных batches.
Итоговый report отсутствует. [resume-validation.py](resume-validation.py)
не запускает обучение и не меняет исходную validation.

Сначала `--check-only`: проверяет релиз, успешные этапы train/merge, идентичность
префикса val и воспроизводит историю пакет за пакетом. Результат каждой из 372
записей должен точно совпасть с сохранённым. Иначе восстановление прекращается.
История использует сумму сохранённых batch seconds; простой/загрузка/прогрев не
увеличивают возраст восстановленного кеша. Незаписанные задержки I/O не могут быть
восстановлены точно; наблюдаемые расхождения префикса вызывают отказ, а не правку.

После прогрева модель генерирует только оставшийся хвост batch=2. История
восстанавливается после сброса прогрева, затем использует активные часы процесса.
Progress продолжает общий счётчик. Новая папка — validation-recovery-001 внутри
папки эксперимента; существующая папка восстановления не перезаписывается.

В ней сохраняются полные predictions, metrics, ошибки, calls/batches, доступные
raw-answers, аудит и история, база и сравнение с V100 второй модели. Исходные
файлы проверяются по хешам до/после. При отсутствии/обрыве старого raw capture
полнота исходных текстов явно отмечается отдельно от полноты результатов.

report.status=quality_complete и protocol=local-inference-v2-recovered намеренно
отличаются от непрерывного benchmark. Длительности пакетов можно сложить без
простоя; пик CUDA первой части при аварии утрачен и записывается null. Новые
пики относятся только к хвосту. Результат нельзя выдавать за непрерывную ресурсную
точку или усреднять с ней без пояснения.

Локально проверены точный replay первых 372 и последующих 11 записей реального
сохранённого V100-прогона, отказ на изменённых ответах, CLI и общий progress.
Новая GPU-генерация и подключение к серверу агентом не выполнялись.
