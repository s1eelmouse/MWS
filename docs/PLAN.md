## 4. Даты, каталог и состояния — главный приоритет

- [x] Код находит временные выражения в реплике-источнике и пересчитывает даты от `started_at`; модель по-прежнему выдаёт ISO-даты. Режим `task` включён по умолчанию: `continue-002` даёт 0.4237 с сериями / 0.4000 без; `continue-003` — **0.4377 с сериями / 0.4351 без**, `state_accuracy` 0.3949, precision/recall/grounding не меняются. Покрытие зависит от атрибута и правила; универсальная привязка всех выражений не реализована. Детали — [DETERMINISTIC.md](DETERMINISTIC.md).
- [x] Календарь и детерминированная постобработка (`feat/temporal-normalization`): прежний `conservative` дал 0.3315 → 0.3398 и оставлен как отдельный режим; новый `task` закрывает отсечение на основной модели.
- [x] Удалять только точные дубликаты: на старом полном val это 102 факта из 1956 (90 — `agreement`), precision 0.3466 → 0.3657 без изменения recall, дат, состояний и grounding. Счётчик — `exact_duplicates_removed`.
- [x] Разобрать остальные `agreement`: у `continue-003` 138 совпало, 809 лишних, 340 пропущено. Основные классы лишних — actor-пересказы («клиент подтвердил…»), слабая/нулевая лексическая поддержка и длинные свободные формулировки; разбор — [RESULTS.md](RESULTS.md), раздел 5. Кандидат precision-режима (`actor + support<0.5`) даёт P 0.4149 → 0.5017 при T −0.0006, но по умолчанию не включён.
- [x] Проверено: длинные `agreement` (>8 токенов) дают precision 0.04; фильтр по длине улучшил бы precision, но ухудшил temporal и является удалением трудных фактов. Не включаем.
- [x] Сопоставление значений с `catalog.json`: точная нормализация меняет 3 поля на полном val и **не меняет официальные метрики**. Разговорные алиасы не включаем: это склеивает разные объекты до извлечения.

## Что отложено

MCP/агент, графовая база, массовая разметка учителем и оптимизация vLLM не входят
в обязательный проход. Возвращаемся к ним только после этапов 2–5.
Разметка учителем не нужна: данные уже размечены организаторами.
