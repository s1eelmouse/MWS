## 1. Что требует кейс

Нужна модель на **0,5–1,5 млрд параметров**, которая держит качество базового
LLM-экстрактора (glm-5.3, zero-shot) и обрабатывает звонок на порядок дешевле.
Итог считается на скрытом тестовом срезе того же формата, что val, включая
adversarial-подмножество с усиленным ASR-шумом.

Критерии жюри, по 0–10 баллов каждый:

| Критерий | Что проверяют |
|---|---|
| Качество решения | Падение `temporal_recall` и `state_accuracy` относительно базы не больше 0,02 при сокращении параметров в 10 раз или GPU-секунд на звонок в 5 раз. **Падение `temporal_recall` больше 0,05 — решение не рассматривается вообще.** |
| Техническая реализация | Воспроизводимое обучение с фиксированными сидами, корректная схема на 100 % ответов, замеры ресурсов по единой методике, устойчивость на adversarial-подмножестве |
| Глубина проработки | Разбор ошибок по типам фактов (изменения состояния отдельно от статических атрибутов), обоснование архитектуры, честная кривая «ресурсы × качество» минимум в трёх точках |
| Презентация и защита | Архитектура и обучение, сравнение с базой, сильные стороны и ограничения, демо вживую или видео |
| Идеи по улучшению | Дообучение на реальных данных без ручной разметки, новые атрибуты, многоязычность |

Что сдаём: веса и конфигурацию инференса; код обучения с сидами; Docker-образ с
HTTP-интерфейсом; отчёт с кривой «ресурсы × качество», задержкой и памятью на CPU и
на одной GPU, разбором ошибок; исходники с документацией; презентацию.

## 2. Наш подход

**Модель:** Qwen3-0.6B. Подтверждённая production/fallback — `4090-continue-002`
(старт с `4090-baseline-001`, LR `1e-4`, +1 эпоха). `4090-continue-003`
с recovery v2 на свежем end-to-end val 2.1 даёт **T 0.4807 / S 0.5201**, 0 отказов,
100 % формата; на шумном val — **T 0.4582 / S 0.4141**. `005`, дообученная на
шумном train 2.1, даёт clean **T 0.4900 / S 0.5522** и noisy **T 0.4751 / S 0.4639**:
на шуме T проходит цель, S пока ниже. Параллельный `4090-continue-v21-001` даёт
clean T 0.4859 / S 0.5056; после интервалов и слоя статусов на тех же ответах —
T 0.5049 / S 0.5297, шумный val не измерен. Qwen3-1.7B не нужен: критерий по
`temporal_recall` закрыт на 0.6B, а полные 1,72B выходят за лимит 1,5B.
Дообучение — QLoRA (4 бита, LoRA r=16, все линейные слои) на выданном
`train.jsonl`. Режим размышлений выключен.

**Валидный JSON по построению.** Локальный инференс ограничивает генерацию
схемой `Facts` через XGrammar: на каждом шаге разрешены только токены, которые
продолжают корректный JSON этой схемы. Формат компактный (`{...,...}`), порядок
полей совпадает с обучающими ответами. Ограничение не меняет prompt и подпись
контракта, поэтому уже обученная модель используется без переобучения. Оно
гарантирует синтаксис, типы и перечисления, но не смысл фактов и не порядок дат
`valid_from`/`valid_to`; их по-прежнему проверяет `src/schema.py`. Отключить
ограничение для контрольного A/B можно через `JSON_CONSTRAINED=0`. Если Triton JIT
не собирается (нет Python-заголовков), задайте `JSON_GRAMMAR_BACKEND=torch_native`.

**Детерминированные даты.** `TEMPORAL_NORMALIZATION=task` включён по умолчанию:
код разбирает явные относительные выражения («вчера», «N дней назад», «с
вторника», «через неделю», «в субботу»), распознаёт типичные ASR-искажения этих
слов, для `action` без времени берёт `started_at`, а в пакетной обработке
переносит дату «принята» внутри серии одного `account_id`. У `continue-002` это
поднимает `temporal_recall` с 0.3566 до **0.4237** (HTTP 0.4000), у
`continue-003` — до **0.4377** (HTTP **0.4351**). Precision, recall и grounding
не меняются; `state_accuracy` 0.3949 у 003. Отключение:
`TEMPORAL_NORMALIZATION=off`. Детали и ограничения —
[docs/DETERMINISTIC.md](docs/DETERMINISTIC.md).

| Модель | Всего параметров | Без эмбеддингов | Слоёв | Контекст |
|---|---:|---:|---:|---:|
| Qwen3-0.6B | 596 049 920 | 440 467 456 | 28 | 40 960 |
| Qwen3-1.7B | 1 720 574 976 | 1 409 410 048 | 28 | 40 960 |

Числа посчитаны по конфигурациям моделей. **Qwen3-1.7B по полному числу параметров
выходит за 1,5B из цели кейса**, а без эмбеддингов укладывается. `src/train.py`
сейчас отказывается обучать модели больше 1,5B по полному числу. Брать 1.7B можно
только после подтверждения ментора, и тогда нужно явно поменять эту проверку.

**Что модель делает сама, а что нет.** Кейс прямо требует вынести из модели то, что
решается детерминированно:

```text
звонок (started_at, реплики с ролями)
  -> модель: объекты, атрибуты, значения, временные выражения как в тексте, turn_idx
  -> код: нормализация дат от started_at, сопоставление с catalog.json,
          словарь отрицаний, роль говорящего из диаризации
  -> код: обновление одно-значных атрибутов, закрытие старых valid_to
  -> факты в схеме организаторов
```

Модель по-прежнему пишет абсолютные даты, но код проверяет и пере задаёт их по
явным временным выражениям в реплике-источнике. Это не меняет prompt и подпись
адаптера. На полном val режим `task` поднял `temporal_recall` выше отсечения
0.371; подробности и измеренные ограничения — в разделе 3 и
[docs/DETERMINISTIC.md](docs/DETERMINISTIC.md).

**Кривая «ресурсы × качество»:** минимум три совместимые точки — batch 1/2/4
на выбранной 0.6B с одинаковыми данными, оценщиком и лимитами; отдельно по
качеству показываются 003, 005 и v21. CPU-точка добавляется, только если полный
val на CPU успевает и остаётся сопоставимым по методике.

с интервалами и слоем статусов на тех же ответах — T 0.5049 / S 0.5297.
Шумный val для него не измерен; интеграция кода продолжается.

Не сделано: замеры CPU и GPU batch1/4 по единой методике, проверка на скрытом
adversarial-срезе, GPU- и vLLM-контейнеры, кривая из трёх точек, презентация.
CPU-образ `compactfactextraction:cpu` уже собран и проверен на `/health` и

## 5. Установка

Все команды выполняются из корня репозитория. Нужен Python 3.12.
Рекомендуется [uv](https://docs.astral.sh/uv/): он сам скачивает Python и подбирает
сборку PyTorch под видеокарту.

    uv venv --python 3.12
    .venv\Scripts\Activate.ps1
    uv pip install torch --torch-backend=auto
    uv pip install -r requirements.txt
    python src/doctor.py --json out/doctor-gpu-first.json

В отчёте doctor должно быть `cuda_available: true`. На Linux/macOS вместо второй
строки: `source .venv/bin/activate`.

Типичные ловушки на Windows:

- PowerShell не даёт запустить `Activate.ps1` — один раз выполните
  `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`, или вызывайте
  `.venv\Scripts\python.exe` напрямую.
- В окружениях uv нет pip. Пишите `uv pip install …`, а не `python -m pip` или `pip`.
- Если `requirements.txt` поставился раньше torch, с PyPI придёт CPU-сборка
  (`+cpu` в версии). Исправление:
  `uv pip install torch --torch-backend=auto --reinstall-package torch`.
- Не обновляйте torch без `--torch-backend`, иначе снова получите CPU-сборку.

Только проверки без видеокарты: `uv pip install -r requirements-cpu.txt`.

## 7. Базовая оценка

    python src/eval.py --gold data/organizer/val.jsonl --pred data/organizer/baseline_pred.jsonl --reference-metrics data/organizer/baseline_metrics.json --json out/baseline-first.json --errors out/baseline-first-errors.jsonl

Для сравнения на части val добавляйте `--limit N` и к базе, и к своей модели:
сравнивать 20 звонков со всеми 383 нельзя.

Файлы результатов не перезаписываются: для повтора нужно новое имя. Сопоставление
идёт по `call_id`, отсутствующие предсказания считаются пропусками.

Известные особенности официального скрипта (не исправляем, а сообщаем):

- `state_accuracy` не учитывает объект: эталон против самого себя даёт 0.8957.
- Сопоставление названий объектов может принять неверный объект.
- `temporal_recall` и grounding считаются только среди уже сопоставленных фактов.
- Даты сравниваются по дням.
- Опубликованные числа базы не совпадают с пересчётом (раздел 1).
- У 34 базовых предсказаний обратные интервалы дат. Они остаются в расчёте.

## 8. Обучение

Короткая проверка, ~11 минут на RTX 4060:

    python src/train.py --limit 64 --max-steps 30 --batch-size 1 --output-dir out/smoke-001

Полное обучение 0.6B: 3 эпохи, по 16 звонков на шаг, 738 шагов, по замеру
короткого запуска **около 3,5–4,5 часов**. Перед запуском закройте браузер, IDE,
живые обои и Docker: в Windows видеопамять расходует и общую память системы.

    $env:MAX_INPUT_TOKENS = "11000"
    python src/train.py --batch-size 1 --save-steps 246 --output-dir out/full-001

- `MAX_INPUT_TOKENS` по умолчанию 8 192. С ним обучение остановится на старте
  из-за 10 длинных звонков. 11 000 покрывает все звонки без обрезки. Переменная
  действует только в текущем окне PowerShell: задайте её и перед `predict.py`.
- `--save-steps 246` сохраняет checkpoint раз в эпоху, и в конце остаются две
  последние эпохи. Если на третьей эпохе `eval_loss` вырастет, можно вернуться ко второй.
- Продолжить прерванный запуск: тот же набор аргументов плюс
  `--resume-from-checkpoint out/full-001/checkpoints/checkpoint-N`.
- Начать **новый** цикл с готового адаптера, а не продолжить старое расписание:
  `--init-adapter-dir out/full-001 --learning-rate 1e-4 --output-dir out/cycle-002`.
  Создаётся новый оптимизатор, а исходный адаптер и хеши его файлов попадают в
  `experiment.json` (`initial_adapter`, `learning_rate`).
- В папку `out/full-001` пишутся `experiment.json` (модель, seed, хеши train/val и
  схемы) и отчёт времени и памяти. Каждый запуск и каждое продолжение получают
  свою папку `attempt-*`: окружение, настройки, `events.jsonl` с loss, `eval_loss`
  и памятью по шагам, итоговый `status.json`.
- Те же шаги одной командой вместе с замерами — `src/run_experiment.py`
  (см. [docs/EXPERIMENTS.md](docs/EXPERIMENTS.md)). Он задаёт `--save-steps 50`,
  число эпох — `--epochs`.

## 9. Слияние, предсказание, оценка

    python src/merge.py --adapter-dir out/full-001 --output out/merged-full-001
    python src/predict.py --input data/organizer/val.jsonl --model out/merged-full-001 --batch-size 8 --output out/pred-full-001.jsonl
    python src/eval.py --gold data/organizer/val.jsonl --pred out/pred-full-001.jsonl --json out/eval-full-001.json

- Слияние вшивает LoRA-адаптер в исходную модель и даёт обычную модель для инференса.
- Генерация по умолчанию идёт с JSON-грамматикой; `constrained_json` в `*.run.json`
  подтверждает это. При `JSON_CONSTRAINED=0` получаем прежний свободный режим для
  сравнения, но синтаксические отказы возможны снова.
- Предсказание сохраняется после каждой пачки, готовый файл не перезаписывается.
  `failed` в логе — ответ, который не разобрался (`invalid_json`, `invalid_source`).
  Такие звонки идут в оценку как пропуски.
- Строка «без дообучения» для таблицы: `--model Qwen/Qwen3-0.6B --with-schema`.
- Ускорение одиночного запроса без переобучения: `$env:PROMPT_LOOKUP_TOKENS = "10"`.

## 12. Правила работы

- Каждая задача — своя ветка от свежего `main`, в `main` только через pull request.
  В описании PR: что закрывает, как проверено, меняется ли общий контракт.
- Изменения `src/schema.py` затрагивают обучение, предсказание, сервис и оценку.
  Предупреждайте команду заранее. Модель предсказывает в формате, на котором
  училась: после смены формата ответа нужно переобучать.
- Данные организаторов, веса, `out/` и ключи в Git не добавляются.
- Результат каждого запуска — в свою папку `out/<имя>`, не поверх чужой.
- Обучение использует только train, val — только для оценки.
- После изменений кода: `python -m unittest discover -s tests` и
  `python -m compileall -q src tests`.
- Числа в отчёте и на защите называем вместе с железом, на котором они сняты.

Правила для ИИ-ассистентов: [AGENTS.md](AGENTS.md).
